## opencode 扫描 winning-ward-newborn 实战

### 执行过程
1. 第一次 ACP spawn：child 有结果但主会话收到的 result 为空
2. 第二次 ACP spawn：超时 600s，仍无结果回传
3. 切 exec opencode：遇到 Windows 命令行截断长提示、Explore Agent 卡住等问题
4. 最终用短提示 + 本地文件清单方式跑通

### ACP 结果回传问题（关键）
- child session `232633ae-bbda-4a85-aa20-e36a3cfd825b.jsonl` 里**实际有完整扫描输出**
- 产物已落盘：
  - `E:\winning-code\akso5\winning-nis-ward\winning-ward-newborn-scan-results.json`
  - `E:\winning-code\akso5\winning-nis-ward\winning-ward-newborn-scan-results-annotated.json`
- 但主会话 completion event 拿到的是空 result
- **根因：ACP 子会话结果写到了本地 transcript，但没有成功 relay 回主会话**
- 这不是 opencode 的问题，是 OpenClaw ACP 回传链路的问题

### opencode 为什么说 skill 不可用但又用了
- opencode 在 ACP 子会话里**不能直接调用 skill() 工具**（skill 未注册到子会话可用列表）
- 但它能**读取 SKILL.md、规则文件、知识库文件作为普通文本**
- 所以它是"参考了 skill 文件内容并手工模仿规则和输出格式"，不是"调用了 skill 运行时"

### exec opencode 扫描结果摘要（6 条）
- 更聚焦，发现了一些不同的高优先问题
- InpatEncNewbornController.java 重复插入
- InpatientParticipantDomainRepositoryImpl.java NPE
- HttpToPost.java OkhttpInterceptor 返回 null
- CertificationService.java .get(0) 缺保护
- DelNewbornService.java 重复调用
- InpatEncNewbornController.java 自赋值空操作

### 教训
1. **ACP 结果回传失败时，应先回捞 child transcript / 落盘文件，不要直接重试**
2. **Windows 命令行会截断长提示，opencode 需要用短提示 + 本地文件清单**
3. **opencode Explore Agent 容易卡住，需要明确约束范围**
4. **扫描前必须先告知用户范围、风险、偏离点**
