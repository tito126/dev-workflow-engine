## ACP 打通
- OpenClaw ACP 连 opencode 从 `backend unavailable` 修复为完全可用。
- 根因：AcpxRuntime 构造时 `healthy=false`，Windows 上 probe 的 `client.start()` 卡死，导致后端永远标记 unavailable；加上 Gateway 启动时 `reconcilePendingSessionIdentities` 在后端注册前执行。
- 两处手动补丁已记录到 TOOLS.md：
  1. `register.runtime-DnI7Bmok.js:219` — `this.healthy = false` → `this.healthy = true`
  2. `server-Cv5hzFG4.js:25975` — 加入 `waitForAcpBackend` 轮询等待（对应 PR #40671）
- ⚠️ 每次 `npm update -g openclaw` 会覆盖这两处，升级后必须重新打补丁。
- 第别用 opencode 完成了修复，我负责测试验证和记录。

## 护士站 skill 全面优化
- 围绕 ACP 打通后的能力，重写全套 `nurse-station-*` skill。
- 核心方向：少重复喂上下文、少主控转述损耗、更适合中任务持续推进、更接近"从消息流变工作流"。
- 新建 `nurse-station-orchestrator` 作为统一入口：
  - 三条路径（light / medium / heavy）
  - 产物落地约定（`work-system/deliverables/nurse-station/{task-id}/`）
  - locator 按需插入规则
  - subagent-execution 定位为"派发层规则"而非"多 agent 管理器"
- 每个 skill 的集成关系都指向 orchestrator。

## 多 agent 讨论结论
- 第别最初设想：创建 analyzer / scanner / executor / verifier 多个 OpenClaw agent，都用 opencode 承接。
- 讨论后共识：现阶段不需要多 agent。角色分工由 skill 层 + prompt 控制，不需要建独立 OpenClaw agent。
- 保留 subagent-execution 作为"派发层规则"，等真正出现"不同角色需要不同模型/权限"时再拆。
