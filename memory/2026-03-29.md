# 2026-03-29

- 今晚在排查 OpenClaw ACP / Claude Code 对接时，发生了一次严重操作失误：本应在精确插件目录 `D:\nvm\v24.9.0\node_modules\openclaw\dist\extensions\acpx` 执行的 `npm install --omit=dev --no-save --package-lock=false acpx@0.3.1`，被误在上层目录 `D:\nvm\v24.9.0\node_modules` 执行，导致 npm 清理了大范围依赖，进一步破坏了 `openclaw` 与 `npm` 本体环境。
- 这是一个明确教训：以后凡是让用户执行带有安装/卸载/清理副作用的命令，尤其是 `npm install`、`pnpm add`、`pip install -t`、`rm`、`del` 这类命令，必须同时明确写出“在哪个目录执行”，不要只给命令本体。
- 更具体地说：如果命令依赖当前工作目录，回复时必须用“先 cd 到 xxx，再执行 yyy”的格式；如果目录非常关键，应额外强调“不要在上级目录执行”。
- 后续凡是涉及 OpenClaw 插件局部安装，也要优先使用这种格式：`cd /d <精确目录>` + 安装命令，并解释为什么不能在更上层目录执行。
- 今晚关于 OpenClaw ACP / Claude Code 对接，还有一条重要技术结论：升级到 `OpenClaw 2026.3.24` 后，`acpx` 变成内置 stock 插件，默认依赖 `acpx@0.3.1`，并且在 Windows 上首先卡在 plugin-local `acpx.cmd` wrapper 校验，不一定立即进入 Claude adapter / session-init 层；要排查这版问题，优先看 `D:\nvm\v24.9.0\node_modules\openclaw\dist\extensions\acpx` 下的 plugin-local `acpx` 是否已安装，以及 gateway 日志里是否出现 `acpx runtime backend ready`。
- 今晚还确认了一个协作规范：当用户要手动执行安装命令时，除了命令本体，必须明确给出“在哪个目录执行”“不要在哪些上层目录执行”“执行完后回传哪两个验证结果”，否则很容易因当前目录错误造成全局环境损坏。
