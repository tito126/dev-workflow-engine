### 已对齐的关键点

1. **章节风格**：按 `4.2.1.2-4.2.1.6` 的风格重写，结构统一为：
   - 4.2.2.2 数据设计
   - 4.2.2.3 输入、输出（按 JSON 格式）
   - 4.2.2.4 模块接口
   - 4.2.2.5 流程逻辑
   - 4.2.2.6 时序图

2. **数据模型口径**：
   - `outpatient_checkin` 作为接诊主表
   - `outpatient_checkin_tag_rel` 只承接**动态标签**，不承接所有展示项
   - `outpatient_checkin_record` 记录全过程业务动作，不只记录 checkout
   - `outpatient_checkin_participant` 记录医生/治疗师/护士等参与者
   - `outpatient_checkin_preference` 记录患者偏好/备注
   - `outpatient_checkin_sync_status` 用于三方成功我方失败的补偿处理

3. **标签口径**：
   - 不再使用“固定标签”表述
   - 改为：
     - **列表直接展示项**：由主表字段、参与者信息、去向信息、聚合结果直接展示，不进标签表
     - **动态标签**：由外部系统标签算法命中后，写入 `outpatient_checkin_tag_rel`
   - 动态标签示例：新医嘱、作废医嘱、修改医嘱、缴费提醒、等候时长超时等

4. **分流口径**：
   - 参考 `4.2.3 分流` 章节
   - 分流核心业务由**分流组件/分诊系统**完成
   - 当前章节只负责：
     - 准备分流弹框上下文数据
     - 打开分流组件
     - 接收分流完成后的回写结果

5. **预问诊口径**：
   - 参考 `4.2.4 预问诊` 章节
   - 当前章节不重复设计预问诊逻辑和数据结构
   - 只描述调用预问诊接口并展示结果

6. **检查患者状态**：
   - 暂按和康复治疗一致的状态流转设计
   - 但用户要求“康复治疗这块先保留现状”，后续如产品再确认可调整口径

7. **逆流程和补偿**：
   - 已补入：
     - 取消分流 / 回退分流结果
     - 取消回诊标记 / 回退回诊入队
     - 取消结束就诊
     - 撤销提前结束就诊
     - 三方成功我方失败的补偿方案
   - 处理原则：幂等 + 同步状态记录 + 指数退避重试 + 定期对账修正

8. **预留项**：
   - “查阅状态 / 新废改提醒”落库方向合理，但当前**尚未与产品对齐**
   - 暂不正式落库实现，后续需和产品确认后补设计
