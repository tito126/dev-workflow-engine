# 2026-02-26 日志

## 日志巡检项目讨论

### 背景
第别想在企微（卫宁服务对话框）用自然语言触发日志巡检，输入类似"帮我巡检浙江省中生产环境微服务护士站xx时间段的生产日志"，然后收到巡检报告。

### 技术架构
```
企微消息 → [待建的桥接层] → OpenClaw
                ↓
    1. 调用工具组API开端口
    2. 下载日志（普通gz / Loki查询）
    3. Skill分析生成报告
                ↓
        报告推回企微
```

### 环境情况
- 连接现场通过 wxp（运维工具），打开端口访问服务器（有跳板机）
- 日志来源两种：
  1. 普通服务器：每 200MB 生成一个 gz 压缩包（压缩后约 20MB）
  2. K8s 服务器：Loki 日志，需开通端口访问
- 端口目前需手动关闭
- 工具组 API 暂未提供，但可手动开端口跑流程

### 设计要点

#### 1. 日志预处理（必须）
200MB 文本超 token 限制，需预处理：
- 只提取 ERROR / WARN / FATAL 级别
- 提取慢接口日志（响应时间 > 阈值）
- 统计异常出现频次
- 输出 <1MB 摘要给 AI 分析

#### 2. 抽象层设计
统一指令接口，用户不用关心底层是 K8s 还是普通服务器：

**环境配置文件** `config/environments.json`:
```json
{
  "浙江省中": {
    "type": "k8s",
    "loki": {
      "host": "10.x.x.x",
      "port": 3100,
      "labels": { "namespace": "nursing-prod", "app": "nurse-station" }
    },
    "portApi": { "openUrl": "http://wxp-api/open", "closeUrl": "http://wxp-api/close", "hospitalId": "zjsz" }
  },
  "某某医院": {
    "type": "traditional",
    "ssh": { "host": "跳板机IP", "logPath": "/data/logs/nurse-station/", "filePattern": "app.*.log.gz" },
    "portApi": { "openUrl": "...", "hospitalId": "xxx" }
  }
}
```

**Skill 目录结构**:
```
workspace/
├── skills/
│   └── log-inspect/
│       ├── SKILL.md          # Skill 说明
│       ├── inspect.py        # 主逻辑（路由 + 拉日志 + 预处理）
│       ├── loki_fetcher.py   # Loki 查询封装
│       ├── gz_fetcher.py     # 传统服务器日志拉取
│       └── preprocess.py     # 日志预处理
├── config/
│   └── environments.json     # 环境配置
```

#### 3. 巡检报告内容
- 错误统计（ERROR/WARN 数量、类型分布）
- 错误详情（Top N 高频错误 + 堆栈）
- 慢接口统计（响应时间 > 阈值的接口列表）
- 趋势分析（错误是否集中在某个时段）
- 建议/结论

**待确认**: 慢接口阈值是多少？500ms？1s？3s？

### 分阶段计划
