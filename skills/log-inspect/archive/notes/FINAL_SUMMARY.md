## 📋 用户需求回顾

### 需求 1：错误分类优化
**问题**：
- 报告中有"Other"这种摸不着头脑的分类
- 分类名称是英文（NullPointerException、SQLException 等）
- 统计数量过大（搞不清楚怎么统计的）

**解决方案**：
- ✅ 所有分类改为中文名称
- ✅ 细化分类，新增多种错误类型
- ✅ 每个分类都有优化建议
- ✅ 按 traceId 去重，统计准确

### 需求 2：日志拉取对齐
**问题**：
- loki_fetcher 和 tool_api_fetcher 都是生成 log 的
- 传统服务器是通过接口下载的 log
- 应该在哪个环节对齐？

**解决方案**：
- ✅ loki_fetcher：在拉取阶段过滤（两阶段拉取）
- ✅ tool_api_fetcher：在分析阶段过滤（--filter-by-error-trace）
- ✅ 最终效果：两种方式都只分析"有问题的 traceId"

### 需求 3：ERROR 日志缺少上下文
**问题**：
- loki_fetcher 只拉取 ERROR/WARN 级别的日志
- 丢失了同一 traceId 的其他日志（INFO、DEBUG 等）
- 无法看到完整调用链

**解决方案**：
- ✅ 实现两阶段拉取（--with-context）
- ✅ 先拉 ERROR/WARN，提取 traceId
- ✅ 再针对每个 traceId 拉取完整日志

### 需求 4：慢接口分析不够深入
**问题**：
- 只知道"慢了"和"总耗时"
- 不知道"慢在哪"
- 无法精准优化

**解决方案**：
- ✅ 创建慢接口深度分析器
- ✅ 识别调用链中的关键步骤
- ✅ 计算每个步骤的耗时
- ✅ 标注瓶颈并生成优化建议

## 📊 使用指南

### K8s 环境（完整流程）

```bash
# 1. 拉取日志（两阶段模式，保留完整上下文）
python loki_fetcher.py \
  --grafana http://127.0.0.1:16291 \
  --app winning-winex-ward-pbc \
  --start "2026-03-09 08:00" \
  --end "2026-03-09 10:00" \
  --with-context \
  --output with_context.log

# 2. 分析日志（标准模式）
python preprocess.py with_context.log -o digest.json

# 3. 生成报告
python generate_html_report_v2.py \
  digest.json \
  report.html \
  "医院名称" \
  "服务名称"
```

### 传统服务器（完整流程）

```bash
# 1. 下载日志（全量）
python tool_api_fetcher.py \
  --base-url http://172.16.9.87:8089 \
  --app-id 9380 \
  --env-id xxx \
  --output all.log

# 2. 分析日志（过滤模式，只分析有问题的 traceId）
python preprocess.py all.log \
  --filter-by-error-trace \
  -o digest.json

# 3. 生成报告
python generate_html_report_v2.py \
  digest.json \
  report.html \
  "医院名称" \
  "服务名称"
```
