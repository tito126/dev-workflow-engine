# Superpower Overrides

在本技能中调用 `superpowers:*` 时，不直接接受其默认行为。始终按下面的包装调用规则执行。

## 通用规则

1. 先由本技能准备输入，再调用下游技能。
2. 下游技能不得重新定义需求范围、任务边界或阶段顺序。
3. 下游技能输出只作为当前阶段的中间产物或辅助结论，不直接视为最终交付物。
4. 如果下游技能输出超出当前阶段，裁剪后再使用。
5. 下游技能不得直接执行 `git commit`；提交建议只能作为草稿返回。
6. 如果下游技能默认行为与本技能冲突，以本技能为准。

## `superpowers:brainstorming`

### 输入

调用前先整理并传入以下内容：

- `产品业务分析.md` 的关键结论
- `代码实现分析.md` 的关键结论
- 需求摘要
- 业务约束
- 技术边界
- 已知上下文
- 待确认问题

### 允许输出

只接受以下结果：

- 设计澄清结论
- 方案比较
- 关键风险
- 技术取舍
- 待确认项

### 禁止输出

不接受以下内容作为有效结果：

- 详细设计文档
- 泛化实施计划
- 任务拆分
- 编码步骤
- 测试清单
- 与当前需求无关的延展建议

### 接入方式

- 将输出整理成设计澄清结论。
- 先裁剪、去重、补充上下文，再写入 `PRD/<需求号>/设计澄清.md`。

## 后续 `superpowers` 规划或研发技能

### 输入

只允许以下输入进入下游技能：

- 当前需求分析产物
- 当前设计澄清文档
- 已确认任务信息

### 允许输出

只接受当前阶段直接需要的结果，例如：

- 当前阶段的实施建议
- 与当前任务直接相关的编码或测试建议
- 当前阶段的风险和依赖

### 禁止输出

不接受以下内容覆盖本技能主流程：

- 重新定义需求范围
- 跳过设计澄清直接进入开发
- 重排既定阶段顺序
- 将前端和后端任务重新合并
- 直接执行 `git commit`

### 接入方式

- 仅抽取与当前阶段相关的部分纳入本技能流程。
- 其余输出视为补充信息，不作为强制动作。
- 如果下游技能给出提交命令或提交动作，只保留为草稿，不执行。

## `superpowers` planning / write-plan 类技能

### 输入前置规则

在调用 planning / write-plan 类技能之前，先施加以下约束：

- 所有计划文档必须保存到 `PRD/<需求号>/plans/`
- 输出语言默认使用中文
- 计划文档必须包含以下部分：背景、目标、范围、风险、步骤、验证方式
- 计划产出后的提交约束必须继续遵循本技能的 [commit-rules.md](commit-rules.md)

### 允许输出

只接受满足以下条件的计划结果：

- 文档输出到 `PRD/<需求号>/plans/`
- 内容为中文，除非用户明确要求其他语言
- 章节至少包含：背景、目标、范围、风险、步骤、验证方式

### 禁止输出

不接受以下结果作为有效计划：

- 输出到 `PRD/<需求号>/plans/` 之外的目录
- 缺少必填章节
- 未说明验证方式
- 与本技能提交约束冲突的提交建议或提交步骤
- 直接执行 `git commit`

### 接入方式

- 将计划文档视为后续研发阶段输入，而不是替代本技能主流程。
- 如果 planning / write-plan 技能默认输出不满足上述要求，重写后再落盘。
- 如果其产出包含提交动作，仅保留文本建议，不执行任何提交。
