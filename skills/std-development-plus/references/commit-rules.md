# Commit Rules

在提交代码前，强制执行以下规则。

## 基本约束

1. 只允许把代码提交到任务工作项，禁止直接提交到需求工作项。
2. 前端代码和后端代码必须分别提交到对应类型的任务。
3. 下游 `superpowers` 技能不得直接执行 `git commit`；所有提交必须回到本技能统一处理。

## Commit Message

所有提交信息必须以任务号开头：

```text
#<任务号> <提交描述>

<详细说明，可选>
```

示例：

```text
#12345 实现用户登录功能

- 添加用户登录接口
- 实现 JWT Token 认证
- 添加登录表单验证
```

## 任务类型与代码类型匹配

| 任务类型 | 任务标题特征 | 允许提交内容 |
| --- | --- | --- |
| 前端任务 | `[AI前端]` | `.vue`、`.tsx`、`.jsx`、样式文件、前端组件等 |
| 后端任务 | `[AI后端]` | `.cs`、`.java`、接口、服务、数据访问层等 |

如果提交内容与任务类型不匹配，拒绝提交并要求用户修正。

## 提交前检查

在执行 `git commit` 前，至少验证以下事项：

1. 任务号对应的工作项类型确实是任务。
2. 任务号与当前需求流程中记录的任务一致。
3. 本次改动的代码类型与任务类型一致。

如果任一检查失败，立即中止提交。
