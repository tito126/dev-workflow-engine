# TFS Workflow

在用户要求从 TFS 需求启动研发时，按以下顺序处理。

## 获取需求内容

1. 要求用户提供需求工作项 ID。
2. 只接受附件中的需求分析产物；必须识别出 `产品业务分析.md` 和 `代码实现分析.md` 两类文件，允许文件名前带需求号等前缀。
3. 下载并保存分析文件到 `PRD/<需求号>/`，保留足够信息让后续步骤能区分这两类文件。
4. 如果附件不可用，或任一分析文件缺失，立即终止当前流程。
5. 终止时明确提示用户：必须先使用 `std-req-analysis-plus` skill 完成需求分析，并产出这两份文件后，才能继续使用本 skill。

## 忽略本地产物

在写入需求资料前，先确保项目根目录 `.gitignore` 至少包含以下规则：

```text
PRD/
docs/plans/
```

## 任务处理

如果用户未直接提供任务号，按以下顺序处理：

1. 查询需求下的现有子任务。
2. 向用户展示已有任务列表，允许选择已有任务、创建新任务，或手动输入任务号。
3. 选择已有任务时，获取任务详情并保存到 `PRD/<需求号>/任务信息.md`。
4. 手动输入任务号时，获取任务详情并保存到 `PRD/<需求号>/任务信息.md`。

## 创建新任务

创建任务前，先读取 `PRD/<需求号>/设计澄清.md`，判断研发范围：

| 任务类型 | 判断条件 | 标题格式 |
| --- | --- | --- |
| 前端任务 | 包含 UI、前端、页面、组件等内容 | `[AI前端] <需求标题>` |
| 后端任务 | 包含 API、接口、服务、数据库等内容 | `[AI后端] <需求标题>` |

创建任务时使用以下默认规则：

- 工作项类型：任务
- 标题`title`：`[任务类型] <需求标题>`
- 任务描述`description`：`[AI-CODING] <需求标题>` 禁止使用markdown语法
- 完成日期`finishDate`：当前时间向后顺延 1 天
- 评估工时`originalEstimate`：默认 4
- `parentId`：关联到当前需求
- 指派者：默认为空，除非用户另有要求，注意不能为`未分配`
- 标签`tag`: `AI-CODING`

创建后记录新任务号，并将任务信息保存到 `PRD/<需求号>/任务信息.md`。

## TFS 标记

在设计澄清完成后，调用 `tfs-query`工具，为需求追加 `AI-CODING` 标记。
