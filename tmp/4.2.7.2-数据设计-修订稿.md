# 4.2.7.2 数据设计（数据模型/库表结构）

## 4.2.7.2.1 核心数据流转图

| 数据对象 | 说明 |
| --- | --- |
| 医生站医嘱主表 | 继续作为医嘱主数据源，负责医嘱主记录、医嘱状态、签收结果及医生站已具备的业务能力 |
| 护士站医嘱辅助扩展表 `outp_nurse_order_ext` | 作为本模块新增轻量辅助表，仅承接护士站自有且需持久化的少量辅助业务字段 |
| 外部系统业务表 | 如药房、收费、检查、检验、治疗等系统业务数据，仍由对应系统负责，不在本模块重复建表 |

其中，`outp_nurse_order_ext` 仅用于承接护士站自有业务字段，不承接医嘱主状态、签收主结果、收费主结果及外部系统权威结果。

整体数据流转关系如下：

1. 医生站完成医嘱开立、签署、作废、转录及签收等主流程处理，相关主数据保留在医生站权威表中。
2. 护士站查询医嘱处理页面时，以医生站返回的医嘱主数据为基础，按需关联 `outp_nurse_order_ext` 组装页面展示内容。
3. 护士进入医嘱处理页面后，调用医生站接口实时获取当前医嘱可编辑属性范围，据此控制页面可编辑项。
4. 护士对护士站自有业务字段进行维护时，更新 `outp_nurse_order_ext`。
5. 药房、收费、检查、检验、治疗等系统返回的业务主结果，仍以对应系统为准，护士站仅做展示、提醒或追溯，不在本模块重复落主数据。

## 4.2.7.2.2 设计目标

本模块数据模型设计需满足以下目标：

1. 以门诊医生站现有医嘱主表为主数据源，护士站不重复建设医嘱主表及其主状态体系。
2. 复用医生站既有医嘱处理能力，避免在护士站重复建设签收、状态管理、可编辑规则等能力。
3. 仅为护士站自有业务设计轻量辅助扩展表，承接明确、自有、需持久化的少量辅助字段。
4. 保持与医生站、药房、收费、检查、检验等系统的数据职责边界清晰，不复制外部系统权威结果。
5. 为后续接口集成、页面展示及问题追溯提供稳定且可控的数据落点，同时避免过度预留和泛化设计。

## 4.2.7.2.3 设计原则

### 4.2.7.2.3.1 主从分责原则

医生站继续作为医嘱主数据和主业务能力的权威来源，承接以下核心语义：

- 医嘱主记录及明细
- 医嘱主状态
- 医嘱签收结果
- 医嘱变更标识
- 医生站已具备的可编辑属性规则
- 医嘱处理过程中已由医生站或外部系统负责的主业务结果

护士站仅新增辅助扩展表，承接护士站自有且需持久化的少量业务字段，不与医生站主表重复建模。

### 4.2.7.2.3.3 实时能力判定原则

医嘱可编辑属性范围以医生站接口实时返回结果为准，护士站不单独维护可编辑规则快照。

具体原则如下：

- 护士进入医嘱处理页面时，实时调用医生站接口获取当前医嘱允许编辑的属性范围。
- 护士站根据接口返回结果控制页面字段显隐、可编辑态及提交内容。
- 不在 `outp_nurse_order_ext` 中设计 `editable_fields_snapshot` 等规则快照字段。
- 如医生站后续调整可编辑规则，护士站无需额外维护本地规则数据。

### 4.2.7.2.3.4 差异化承接原则

不同医嘱类型在护士站侧的处理范围应以“护士站是否自有、是否必须持久化”为判断标准。

当前明确原则如下：

- 医嘱主状态、签收结果、收费主结果等权威业务数据，不由护士站辅助表承接。
- 对于医生站已具备处理能力的字段，不在护士站重复落库。
- 对于护士站明确自有、且页面处理和后续追溯确需持久化的字段，可以在辅助表中保留。
- 对于尚未明确归属、尚未稳定或仍待外部确认的字段，本次不预留兜底字段，不使用通用 JSON 承接。

## 4.2.7.2.4 表结构设计

### 4.2.7.2.4.1 表1：门诊护士站医嘱辅助扩展表（`outp_nurse_order_ext`）

**用途：**  
用于存储护士站对医生站医嘱的少量辅助扩展数据，仅承接护士站自有且需持久化的业务字段。

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 主键，自增 |
| nurse_order_ext_id | VARCHAR(64) | 扩展记录唯一标识 |
| source_system | VARCHAR(32) | 来源系统，默认门诊医生站 |
| order_id | VARCHAR(64) | 医生站医嘱 ID |
| order_no | VARCHAR(64) | 医嘱号快照 |
| encounter_id | VARCHAR(64) | 本次门诊就诊 ID |
| checkin_id | VARCHAR(64) | 护士站接诊记录 ID |
| patient_id | VARCHAR(64) | 患者 ID |
| patient_name | VARCHAR(128) | 患者姓名快照 |
| order_category | VARCHAR(32) | 医嘱类别，如 DRUG / EXECUTION / PROCEDURE / EXAM / LAB / OTHER |
| order_item_name | VARCHAR(256) | 医嘱项目名称快照 |
| doctor_id | VARCHAR(64) | 开立医生 ID 快照 |
| doctor_name | VARCHAR(128) | 开立医生姓名快照 |
| retain_drug_mode | VARCHAR(32) | 留药方式 |
| nurse_remark | VARCHAR(1000) | 护士备注 |
| version_no | INT | 乐观锁版本号 |
| created_time | DATETIME | 创建时间 |
| created_by | VARCHAR(64) | 创建人 |
| updated_time | DATETIME | 更新时间 |
| updated_by | VARCHAR(64) | 更新人 |

#### 关键字段说明

**留药方式字段**

`retain_drug_mode` 用于承接护士站自有业务中的留药方式信息，建议枚举如下：

- `CENTER_RETAIN`：中心留药
- `PHARMACY_RETAIN`：药房留药
- `NO_RETAIN`：不留药

该字段属于护士站自有业务字段，可由护士站负责维护。

**护士备注字段**

`nurse_remark` 用于记录护士站在医嘱处理过程中的补充说明信息。  
该字段仅作为护士站侧辅助说明，不承接医嘱主状态或外部系统权威业务结果。

#### 数据来源

本表数据主要来源如下：

- 医生站医嘱主数据的基础关联信息
- 护士站自有业务录入结果
- 护士站页面处理过程中产生的辅助备注信息

#### 设计说明

1. 本表不是医嘱主表，不承接医嘱主状态语义。
2. 本表与医生站医嘱主记录通过 `source_system + order_id` 唯一关联。
3. 本表仅承接护士站自有且需持久化的少量辅助字段。
4. 医嘱可编辑属性范围以医生站接口实时返回为准，不单独维护规则快照字段。
5. 当前不设置通用扩展 JSON 字段，避免形成泛化兜底设计。
6. 后续如出现明确、稳定且确需持久化的新字段，再单独评估是否新增固定列或拆分子表。

## 4.2.7.2.5 数据流转说明

### 4.2.7.2.5.1 医嘱查看

护士站查询医嘱处理页面时，以医生站医嘱主数据为基础，按需关联 `outp_nurse_order_ext` 补充护士站自有辅助信息，共同生成页面展示结果。

### 4.2.7.2.5.2 医嘱签收

护士站如需发起医嘱签收操作，由护士站调用医生站接口完成处理。  
签收结果、签收状态及相关业务语义均以医生站返回结果为准，护士站不在 `outp_nurse_order_ext` 中单独维护签收状态体系。

### 4.2.7.2.5.3 医嘱属性编辑

护士进入医嘱处理页面时，护士站实时调用医生站接口获取当前医嘱允许编辑的属性范围。  
护士站根据接口返回结果控制页面可编辑项。  
如编辑内容属于医生站主数据范围，则调用医生站接口更新；如编辑内容属于护士站自有辅助字段，则同步更新 `outp_nurse_order_ext`。

### 4.2.7.2.5.4 外部结果承接

药房、收费、检查、检验、治疗等外部系统返回的业务主结果，不在护士站本模块重复建表或重复落主数据。  
护士站仅在页面展示、提醒或追溯需要时，通过接口查询或展示对应系统结果，不在本表中泛化承接。
