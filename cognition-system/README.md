# 认知协作系统

这不是一个新的专项，也不是对 `work-system/` 的替代。

它是位于项目执行层之上的协作认知层，用来持续沉淀：
- 第别是谁，如何判断，如何取舍
- 我们如何配合更顺，哪里容易产生偏差
- 一个项目中的经验，如何迁移到下一个项目

目标不是把聊天全部存档，而是让日常互动逐步转化为更好的协作质量，并反哺专项落地。

## 系统定位

- `work-system/`：负责推进事情
- `cognition-system/`：负责理解人、理解协作、理解迁移规律
- `memory/`：负责保留每日过程痕迹
- `MEMORY.md` / `USER.md`：负责沉淀长期稳定记忆和用户画像摘要

## 核心模块

### 1. 自我画像
记录第别较稳定的价值观、思维模式、工作习惯、行为偏好、决策原则、关注方向。

文件：`cognition-system/self-model.md`

### 2. 协作画像
记录双方协作中已验证有效的模式，以及容易出现的误差、提醒点和配合规则。

文件：`cognition-system/collaboration-model.md`

### 3. 迁移机制
记录如何把一个项目中的经验、教训、检查点、模板和判断规则迁移到下一个项目。

文件：`cognition-system/transfer-rules.md`

### 4. 系统联动
定义认知层如何反哺 `work-system/`，避免形成两套互不相干的记录系统。

文件：`cognition-system/system-link.md`

## 使用原则

- 不保存全部聊天，只沉淀有长期价值的部分
- 不把认知系统再建成正式专项
- 不频繁新增层级，先在现有骨架内稳定运转
- 优先记录有证据支撑的判断，少写空泛标签
- 区分长期稳定特征与阶段性策略
- 所有认知结论最终都要能帮助更好地推进事情

## 推荐工作流

1. 日常聊天和专项推进中的关键信息，先进入 `memory/YYYY-MM-DD.md`
2. 能正式推进的事项，进入 `work-system/`
3. 稳定的偏好、规律、判断原则，再提炼进 `cognition-system/`
4. 长期稳定且足够确认的内容，再压缩同步到 `USER.md` 或 `MEMORY.md`

## 当前起步方式

第一阶段先不求全，只做三件事：
- 从“日志猎人”这次合作里提炼第一批协作规律
- 逐步建立第别的自我画像 v0.1
- 形成第一版跨项目迁移规则

后续再根据实际使用情况增补结构，而不是先设计一整套过重体系。
