# 系统联动

这份文档说明 `cognition-system/` 如何与 `work-system/` 联动。

## 分工

### `work-system/`
负责：
- 专项推进
- Daily Focus
- Daily Summary
- 提醒、灵感、临时事项
- 项目风险、里程碑、下一步动作

### `cognition-system/`
负责：
- 第别的长期画像
- 协作规律
- 决策模式
- 跨项目迁移规则
- 对系统本身的纠偏与演化

## 联动规则

### 1. 日常互动先不过度抽象
聊天或专项推进中出现的重要信息，先记事实，再视情况提炼认知结论。

### 2. 认知结论必须反哺执行
如果一条认知判断不能帮助更好地推进项目、识别风险或改进协作，就不急着写进认知系统。

### 3. 执行问题反向触发认知更新
当项目中反复出现某类偏差，比如立项偏差、表达跑偏、层级混乱，应回头更新 `cognition-system/`，而不是只在单个项目里修补。

### 4. 长期稳定后再进入摘要层
`cognition-system/` 是分析层，`USER.md` 和 `MEMORY.md` 是摘要层。只有足够稳定、反复验证过的内容，再进入摘要层。

## 第一阶段联动动作

- 从“日志猎人”中提炼第一份项目复盘
- 从复盘中抽出跨项目检查点
- 将对第别决策方式的新理解持续补进 `self-model.md`
- 将协作中的偏差和纠偏经验补进 `collaboration-model.md`
- 对于执行型 Agent 这类能力建设事项，优先沉淀到 `cognition-system/execution-agent-mechanism.md`，而不是误收编为业务专项
