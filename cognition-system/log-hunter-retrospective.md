# 日志猎人项目复盘

这是认知协作系统中的第一份样板复盘。

目标不是重复项目档案，而是回答三件事：
- 这次项目哪里做对了
- 哪里偏了，为什么偏
- 哪些经验应迁移到下一个项目

## 一、项目总体判断

“日志猎人”不是一个失败项目，反而是一个很扎实的起点项目。

它的价值在于：
- 项目本体是真实可运行的，不是为了比赛临时拼出的展示物
- 产出链条较完整，包含能力、报告、答辩材料、讲稿、Q&A、运行代码包
- 这次合作首次完整经历了“做能力 -> 做表达 -> 做临场支撑 -> 做复盘迁移”的全过程

它的不完美也很典型：
- 项目启动时更偏“真实工具建设”，不是从比赛型项目视角反推立项
- 前期“故事线”和“价值主线”定得偏晚
- 一度把技术路径讲得太重，压过了业务价值和治理价值

## 二、这次做对了什么

### 1. 选题是真问题，不是空题
日志巡检本身有真实业务价值，且已经沉淀为能跑的工具链，这让整个项目具备长期生命力，而不只是一次性参赛作品。

### 2. 项目本体有硬支撑
核心能力不是 PPT 话术，而是已有真实成果支撑，包括：
- 两阶段日志拉取与完整链路补强
- 四级分组、代表 trace、调用方识别、慢接口分析
- K8s 与传统服务器双路径适配
- HTML 报告输出能力

### 3. 中后期纠偏是有效的
后续从“材料堆叠”逐步收敛到更清晰的答辩表达，并最终稳定到“事后响应痛点、持续优化方向、验证闭环机制”这条更贴近业务价值的主线。

### 4. 临场材料补得完整
最后不仅有 PPT，还有讲稿、口语版、Q&A、运行代码包。这说明交付意识已经从“做页面”提升到“做完整上场方案”。

## 三、这次差在哪里

### 1. 立项时没有先按比赛型项目思考
项目虽然真实，但起步时更像“做一个能用的工具”，而不是“做一个适合比赛评审理解和认可的作品”。

直接后果是：
- 前期积累了很多内容，但没有天然形成稳定叙事
- 到答辩阶段才开始高强度补故事线、主线、证据组织和评委视角

### 2. 主线确立偏晚
直到后面才逐步明确：
- 不是因为没有日志排查方式
- 不是因为环境不统一才做这个
- 真正主线是从被动排障走向主动巡检与持续治理

这条主线一旦晚定，前面的很多表达就容易散。

### 3. 技术表达一度压过价值表达
在答辩打磨中，多次暴露出一个问题：
- 技术策略本身没错
- 但如果把“两阶段分析、环境适配、完整链路补齐”讲得过重，就容易显得像技术炫技
- 用户更认可的是：这些技术设计最终服务于“发现问题、提出建议、推动改进、再次验证”的闭环

### 4. 证据资产组织偏晚
成果截图、Q&A、运行代码包、最终口播材料，大多是在后期系统补齐。
如果在项目推进过程中更早建立“证据资产池”，收口会更从容。

## 四、立项时漏想了什么

如果重新开始，这些问题应该在立项时就先问：

### 1. 这到底是个什么类型的项目
- 真实落地型项目
- 比赛型项目
- 汇报展示型项目
- 长期治理型项目

日志猎人实际上同时具备多种属性，但前期没有明确主属性，导致表达一度摇摆。

### 2. 评委会因为什么认可它
应该更早回答：
- 是因为真实问题够硬
- 是因为 AI 介入方式够清晰
- 是因为产出够完整
- 还是因为后续治理空间够大

### 3. 最强证据是什么
立项时就应该反推：
- 三个最能打动人的成果证据是什么
- 哪些截图、案例、指标需要一路积累
- 最终答辩时最该摆出来的不是“做了很多”，而是“凭什么相信它真的有价值”

### 4. 哪些质疑一定会出现
比如：
- 这是不是只适合某些医院
- AI 真正做了什么
- 是否只是分析，没有修复
- 是否只能做日志，不具备更广泛价值

这些问题如果前期就预演，后面 Q&A 会更从容。

## 五、这次形成的迁移结论

### A. 对比赛型/汇报型项目的迁移结论
1. 立项时就要先定一句价值主线
2. 项目推进时同步建立证据资产池
3. 页面、讲稿、Q&A 不要分三个阶段做，应该同步推进
4. 技术亮点必须服务于价值表达，不能反客为主
5. 如果项目真实但不够“讨巧”，就更要强化评委视角和证据组织

### B. 对日常协作的迁移结论
1. 当一个项目开始出现“材料很多但故事讲不顺”时，说明主线定义不够早
2. 当技术内容越讲越多时，要主动检查是否压过了价值表达
3. 当项目接近交付时，必须从“产出完成”切换到“上场完整”思维
4. 复盘不能只留在项目文件里，还要迁移进认知协作系统

### C. 对第别判断方式的新认识
1. 更重视“真实价值”而不是形式上的复杂和炫技
2. 对主线敏感，能持续察觉并纠正表达偏航
3. 不满足于做出内容，更在意内容是否站得住、讲得清、能延展
4. 愿意为结构质量投入额外打磨，不轻易接受只是“赶出来”的版本
