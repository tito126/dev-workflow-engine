## 4.2.2.6.1 三方推送排班时序图

```plantuml
@startuml
hide footbox

autonumber

actor "三方排班系统" as ThirdSchedule
participant "排班接收接口\n/api/third-party/schedule/push" as ScheduleApi
participant "排班处理服务" as ScheduleService
database "outp_resource_sched\n排班主表" as ResourceSched
database "outp_res_sched_detail\n排班明细表" as ResourceDetail
database "outp_schedule_log\n操作日志表" as ScheduleLog

ThirdSchedule -> ScheduleApi: 推送排班数据(requestId, resource, date, details)
ScheduleApi -> ScheduleService: 校验并处理排班请求
ScheduleService -> ScheduleService: 校验必填项/资源/日期/幂等键

alt 参数合法
    ScheduleService -> ResourceSched: 新增或更新排班主记录
    ResourceSched --> ScheduleService: 返回 scheduleId
    ScheduleService -> ResourceDetail: 批量新增或更新时段明细
    ResourceDetail --> ScheduleService: 返回 detailCount
    ScheduleService -> ScheduleLog: 记录排班推送成功日志
    ScheduleService --> ScheduleApi: 返回成功结果
    ScheduleApi --> ThirdSchedule: success(scheduleId, detailCount)
else 参数非法或处理失败
    ScheduleService -> ScheduleLog: 记录排班推送失败日志
    ScheduleService --> ScheduleApi: 返回失败原因
    ScheduleApi --> ThirdSchedule: fail(errorMessage)
end
@enduml
```

```plantuml
database "outp_sched_order_resv\n医嘱预约关联表" as OrderResv
database "outp_schedule_log\n操作日志表" as ScheduleLog

ThirdReservation -> ReservationApi: 推送预约数据(requestId, reservation, orders)
ReservationApi -> ReservationService: 校验并处理预约请求
ReservationService -> SyncStatus: 按 requestId 查询幂等状态

alt 已成功处理
    SyncStatus --> ReservationService: SUCCESS
    ReservationService --> ReservationApi: 直接返回幂等成功
    ReservationApi --> ThirdReservation: success(idempotent=true)
else 未处理
    SyncStatus --> ReservationService: NOT_FOUND / FAILED
    ReservationService -> SyncStatus: 写入 PENDING 状态
    ReservationService -> Reserved: 新增或更新预约记录
    alt 含医嘱信息
        ReservationService -> OrderResv: 写入医嘱关联信息
        OrderResv --> ReservationService: 返回成功
    end
    ReservationService -> SyncStatus: 更新为 SUCCESS / FAILED
    ReservationService -> ScheduleLog: 记录预约推送处理日志
    ReservationService --> ReservationApi: 返回处理结果
    ReservationApi --> ThirdReservation: success/fail
end
@enduml
```

## 4.2.2.6.3 护士手动新增日程时序图

```plantuml
@startuml

autonumber

actor "护士" as Nurse
participant "日程看板页面" as SchedulePage
participant "日程服务" as ScheduleService
database "outp_fixed_resource\n固定资源表" as FixedResource
database "outp_resource_sched\n排班主表" as ResourceSched
database "outp_res_sched_detail\n排班明细表" as ResourceDetail
database "outp_schedule_reserved\n预约/日程表" as Reserved
database "outp_schedule_log\n操作日志表" as ScheduleLog

Nurse -> SchedulePage: 点击“新增日程”并提交表单
SchedulePage -> ScheduleService: 提交资源、日期、时段、标题、备注
ScheduleService -> FixedResource: 校验资源是否有效
FixedResource --> ScheduleService: 返回资源信息
ScheduleService -> ResourceSched: 查询关联排班(如存在)
ResourceSched --> ScheduleService: 返回排班信息
ScheduleService -> ResourceDetail: 校验时段是否冲突
ResourceDetail --> ScheduleService: 返回可用性结果

alt 校验通过
    ScheduleService -> Reserved: 写入手动新增日程记录
    alt 该日程占用排班明细时段
        ScheduleService -> ResourceDetail: 按业务规则更新占用状态
        ResourceDetail --> ScheduleService: 更新成功
    else 不占用排班明细
        ScheduleService -> ScheduleService: 保留为独立手动日程
    end
    ScheduleService -> ScheduleLog: 记录手动新增日程日志
    ScheduleService --> SchedulePage: 返回成功并触发刷新
    SchedulePage --> Nurse: 展示新增成功
else 校验失败
    ScheduleService --> SchedulePage: 返回冲突/资源不可用原因
    SchedulePage --> Nurse: 提示失败原因
end
@enduml
```

## 4.2.2.6.6 逆流程/补偿处理时序图

```plantuml
@startuml
hide footbox

autonumber

actor "三方系统/护士端" as Caller
participant "逆流程处理接口" as ReverseApi
participant "补偿处理服务" as CompensateService
database "outp_resource_sched\n排班主表" as ResourceSched
database "outp_res_sched_detail\n排班明细表" as ResourceDetail
database "outp_schedule_reserved\n预约/日程表" as Reserved
database "outp_sync_status\n同步状态表" as SyncStatus
database "outp_schedule_log\n操作日志表" as ScheduleLog

Caller -> ReverseApi: 发起取消排班/修改排班/取消预约/回调重试请求
ReverseApi -> CompensateService: 按事件类型处理逆流程

alt 取消排班
    CompensateService -> ResourceSched: 查询排班主记录
    CompensateService -> Reserved: 查询是否存在关联预约
    alt 无关联预约
        CompensateService -> ResourceSched: 更新为取消/删除状态
        CompensateService -> ResourceDetail: 更新明细状态
    else 有关联预约
        CompensateService -> SyncStatus: 标记异常待处理/待人工确认
    end
else 修改排班
    CompensateService -> ResourceSched: 更新排班主记录
    CompensateService -> ResourceDetail: 更新明细时段
    CompensateService -> SyncStatus: 记录受影响数据及补偿状态
else 取消预约
    CompensateService -> Reserved: 更新预约状态为已取消
    CompensateService -> ResourceDetail: 释放时段占用
    CompensateService -> SyncStatus: 记录取消同步状态
else 回调失败重试/对账补偿
    CompensateService -> SyncStatus: 查询 FAILED/PENDING 记录
    CompensateService -> CompensateService: 执行重试或对账修正逻辑
    CompensateService -> SyncStatus: 更新最终状态
end

CompensateService -> ScheduleLog: 记录逆流程/补偿处理日志
CompensateService --> ReverseApi: 返回处理结果
ReverseApi --> Caller: success/fail
@enduml
```
