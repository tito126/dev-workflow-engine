## 4.2.4.4.2.5 外部系统写入标签接口

接口地址：`POST /api/outpatient-nurse/tag/push`

功能说明：接收外部系统推送的患者标签数据，写入或更新 `outp_nurse_tag`，并同步记录 `outp_nurse_tag_log`。该接口主要承接三方系统同步或规则计算生成的标签数据，与接诊主表字段保持一定隔离，用于支撑患者列表标签的独立维护与展示。

调用方：门诊、分诊、医生站、收费、病历、入院单等外部系统，或统一标签汇聚服务。

触发时机：
- 外部系统识别出患者身份标签时；
- 外部系统生成医嘱提醒、缴费提醒、病历提醒、入院单提醒等业务标签时；
- 外部系统通知标签失效、撤销或重算时。

请求参数：
- `requestId`；
- `sourceSystem`；
- `sourceEventId`；
- `checkinId`；
- `patientId`；
- `encounterId`；
- `tagList`；
  - `tagTypeCode`；
  - `tagTypeName`；
  - `tagCode`；
  - `tagName`；
  - `tagStatus`（生效 / 失效）；
  - `tagValue`（如有）；
  - `triggerTime`；
  - `expireTime`（如有）；
  - `remark`。

返回结果：
- 是否处理成功；
- 成功写入或更新的标签数量；
- 标签主键集合或处理摘要；
- 是否需要刷新患者列表。

输出示例如下：

```json
{
  "success": true,
  "processedCount": 2,
  "tagResults": [
    {
      "tagId": "TAG-20260419-0001",
      "tagCode": "PAY_REMIND",
      "tagStatus": "VALID"
    },
    {
      "tagId": "TAG-20260419-0002",
      "tagCode": "EMR_REMIND",
      "tagStatus": "VALID"
    }
  ],
  "needRefresh": true,
  "message": "处理成功"
}
```

异常处理：
- 使用 `requestId + sourceEventId` 进行幂等校验；
- 同一标签若已存在当前有效记录，则按更新逻辑处理，不重复生成脏数据；
- 标签失效、撤销、重算需同步记录到 `outp_nurse_tag_log`；
- 失败时写入 `outp_sync_status`；
- 关键处理过程写入统一日志留痕机制；
- 重试与对账策略复用 `4.2.3.5.8`。
