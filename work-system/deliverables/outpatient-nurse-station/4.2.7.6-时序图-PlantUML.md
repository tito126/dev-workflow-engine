## 三、PlantUML 草稿

## 4.2.7.6.1 医嘱签收时序图

```plantuml
@startuml
hide footbox

autonumber

actor "护士" as Nurse
participant "医嘱处理页面" as OrderPage
participant "医嘱签收接口\n/api/outpatient-nurse/order/sign" as SignApi
participant "医嘱签收处理服务" as SignService
participant "门诊医生站医嘱编辑接口/组件" as DoctorOrderApi
database "outp_sync_status\n同步状态表" as SyncStatus
database "outp_nurse_order_ext\n门诊护士站医嘱扩展表" as NurseOrderExt
collections "统一日志留痕机制" as OpLog

Nurse -> OrderPage: 勾选医嘱并点击“签收”
OrderPage -> SignApi: 提交签收请求(requestId, signBatchNo, orders, nurseFields)
SignApi -> SignService: 校验并处理签收请求
SignService -> SyncStatus: 按 requestId + signBatchNo 查询幂等状态
alt 已成功处理
    SyncStatus --> SignService: SUCCESS
    SignService --> SignApi: 直接返回既有处理结果
    SignApi --> OrderPage: success(idempotent=true)
    OrderPage --> Nurse: 展示既有签收结果
else 未处理或处理失败
    SyncStatus --> SignService: NOT_FOUND / FAILED
    SignService -> SyncStatus: 写入 PENDING 状态
    alt 存在护士侧属性变更
        SignService -> DoctorOrderApi: 先更新医生站主数据
        DoctorOrderApi --> SignService: 返回主数据更新结果
    end
    SignService -> NurseOrderExt: 写入/更新护士签收状态与扩展字段
    NurseOrderExt --> SignService: 返回签收结果
    SignService -> SyncStatus: 更新为 SUCCESS / FAILED
    SignService -> OpLog: 记录医嘱签收处理日志
    SignService --> SignApi: 返回处理结果
    SignApi --> OrderPage: success/fail
    OrderPage --> Nurse: 刷新医嘱列表并展示结果
end
@enduml
```

## 4.2.7.6.2 医嘱属性编辑时序图

```plantuml
@startuml
hide footbox

autonumber

actor "护士" as Nurse
participant "医嘱处理页面" as OrderPage
participant "医嘱属性编辑接口\n/api/outpatient-nurse/order/edit" as EditApi
participant "医嘱属性处理服务" as EditService
participant "门诊医生站医嘱编辑接口/组件" as DoctorOrderApi
database "outp_sync_status\n同步状态表" as SyncStatus
database "outp_nurse_order_ext\n门诊护士站医嘱扩展表" as NurseOrderExt
collections "统一日志留痕机制" as OpLog

Nurse -> OrderPage: 点击“编辑”并提交属性修改
OrderPage -> EditApi: 提交编辑请求(requestId, orderId, editableFields)
EditApi -> EditService: 校验并处理编辑请求
EditService -> SyncStatus: 按 requestId + orderId 查询幂等状态
alt 已成功处理
    SyncStatus --> EditService: SUCCESS
    EditService --> EditApi: 直接返回既有处理结果
    EditApi --> OrderPage: success(idempotent=true)
else 未处理或处理失败
    SyncStatus --> EditService: NOT_FOUND / FAILED
    EditService -> SyncStatus: 写入 PENDING 状态
    EditService -> DoctorOrderApi: 校验可编辑字段并更新医生站主数据
    alt 医生站更新成功
        DoctorOrderApi --> EditService: 返回最新主数据结果
        EditService -> NurseOrderExt: 同步更新护士补充字段
        EditService -> SyncStatus: 更新为 SUCCESS
        EditService -> OpLog: 记录医嘱属性编辑日志
        EditService --> EditApi: 返回处理成功结果
        EditApi --> OrderPage: success
    else 医生站更新失败
        DoctorOrderApi --> EditService: 返回失败原因
        EditService -> SyncStatus: 更新为 FAILED
        EditService -> OpLog: 记录失败日志
        EditService --> EditApi: 返回失败原因
        EditApi --> OrderPage: fail(errorMessage)
    end
end
OrderPage --> Nurse: 刷新属性摘要/提示结果
@enduml
```

## 4.2.7.6.5 幂等、重试与对账处理时序图

```plantuml
@startuml
hide footbox

autonumber

actor "调用方" as Caller
participant "业务接口" as BizApi
participant "业务处理服务" as BizService
database "outp_sync_status\n同步状态表" as SyncStatus
database "outp_nurse_order_ext\n门诊护士站医嘱扩展表" as NurseOrderExt
participant "医生站/外部权威结果" as AuthorityResult
collections "统一日志留痕机制" as OpLog
participant "定时对账任务" as ReconcileJob

Caller -> BizApi: 发起业务请求(requestId)
BizApi -> BizService: 转交业务处理
BizService -> SyncStatus: 查询 requestId 幂等状态
alt 已成功处理
    SyncStatus --> BizService: SUCCESS
    BizService --> BizApi: 直接返回既有处理结果
    BizApi --> Caller: success(idempotent=true)
else 未处理或处理失败
    SyncStatus --> BizService: NOT_FOUND / FAILED
    BizService -> SyncStatus: 写入 PENDING 状态
    BizService -> AuthorityResult: 获取/校验权威主结果
    BizService -> NurseOrderExt: 执行业务回写或投影更新
    alt 处理成功
        BizService -> SyncStatus: 更新为 SUCCESS
    else 处理失败
        BizService -> SyncStatus: 更新为 FAILED，并记录 retry_count / next_retry_time / error_message
    end
    BizService -> OpLog: 记录处理日志
    BizService --> BizApi: 返回处理结果
    BizApi --> Caller: success/fail
end

ReconcileJob -> SyncStatus: 扫描失败或待处理记录
SyncStatus --> ReconcileJob: 返回待重试/待对账数据
ReconcileJob -> AuthorityResult: 拉取最新权威主结果
ReconcileJob -> NurseOrderExt: 执行补录/重试/修正
ReconcileJob -> SyncStatus: 更新最终状态
ReconcileJob -> OpLog: 记录对账修正日志
@enduml
```
