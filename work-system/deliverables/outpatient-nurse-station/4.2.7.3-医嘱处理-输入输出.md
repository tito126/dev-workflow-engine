# 4.2.7.3 输入、输出

## 4.2.7.3.1 设计说明

本模块输入输出设计围绕门诊护士站医嘱处理的核心使用链路展开，重点覆盖以下场景：

- 医嘱列表查询与展示；
- 医嘱签收；
- 医嘱属性编辑；
- 医嘱转录；
- 补记账与暂不收费；
- 报价单导入医嘱；
- 医技预约；
- 入院单查看。

其中：

1. 医嘱主数据、医嘱主状态、新废改、审方结果、收费主结果、转录主结果仍以医生站 / HIS / 药房 / 医技系统为准；
2. 护士站侧主要输出 `outp_nurse_order_ext` 中的签收结果、护士补充属性和少量展示投影字段；
3. 护士站允许签收“已签署”及“已作废”医嘱，不允许签收“待确认”及未审批生效的转录医嘱；
4. 若护士在签收前编辑了医嘱属性，则需先调用医生站接口完成属性更新，再回写护士站扩展数据。

## 4.2.7.3.2 医嘱列表查询与展示输入输出

### 4.2.7.3.2.1 场景说明

护士打开患者右侧医嘱处理区域时，系统需加载本次就诊相关的医嘱列表，并展示医生站主状态、护士签收状态、医嘱变更标识、新增标签及可编辑属性摘要。

医嘱列表以医生站医嘱主数据为基础，结合 `outp_nurse_order_ext` 进行展示组装。

### 4.2.7.3.2.2 输入内容

输入内容主要包括：

- 接诊主键；
- 门诊就诊主键；
- 患者主键；
- 医嘱分类筛选条件；
- 是否仅看未签收；
- 医嘱状态筛选条件；
- 页面显示配置版本。

输入示例如下：

```json
{
  "checkinId": "NC-20260418-0001",
  "encounterId": "OP202604180001",
  "patientId": "P00012345",
  "orderCategory": "ALL",
  "onlyUnsign": false,
  "statusList": ["SIGNED", "VOID", "PENDING_CONFIRM"],
  "displayConfigVersion": "NURSE-ORDER-DISPLAY-V1"
}
```

### 4.2.7.3.2.3 输出结果

系统加载成功后，输出结果包括：

- 医生站医嘱列表；
- 护士站扩展属性摘要；
- 页面展示状态；
- 新 / 废 / 改标识；
- 标签信息，如基数药、分批发药、诊间用药、审方结果、收费结果等；
- 是否允许签收、是否允许编辑、是否允许查看详情等页面操作控制信息。

输出示例如下：

```json
{
  "success": true,
  "checkinId": "NC-20260418-0001",
  "items": [
    {
      "orderId": "ORD-10001",
      "orderNo": "OPD-ORD-10001",
      "orderCategory": "DRUG",
      "orderItemName": "阿莫西林胶囊",
      "doctorMainStatus": "SIGNED",
      "nurseSignStatus": "UNSIGNED",
      "displayStatus": "已签署",
      "changeFlag": "NEW",
      "tags": ["诊间用药", "未收费"],
      "canSign": true,
      "canEdit": true,
      "canView": true
    }
  ],
  "message": "查询成功"
}
```

## 4.2.7.3.3 医嘱签收输入输出

### 4.2.7.3.3.1 场景说明

护士在医嘱列表中勾选医嘱后点击“签收”按钮，系统校验医嘱是否允许签收，并在必要时先更新医生站可编辑属性，再回写护士站签收结果。

当前收敛口径如下：

- 可签收：医生主状态为“已签署”或“已作废”的医嘱；
- 不可签收：待确认医嘱、未审批生效的转录医嘱；
- 若签收对象中包含可编辑属性变更，则需先调医生站接口更新主数据；
- 医生已作废且护士完成签收后，页面展示状态为“作废已签收”。

### 4.2.7.3.3.2 输入内容

输入内容主要包括：

- 接诊主键；
- 门诊就诊主键；
- 签收批次号；
- 待签收医嘱列表；
- 护士侧补充属性；
- 签收护士信息；
- 操作时间。

输入示例如下：

```json
{
  "checkinId": "NC-20260418-0001",
  "encounterId": "OP202604180001",
  "signBatchNo": "SIGN-20260418-001",
  "operatorId": "N2001",
  "operatorName": "李护士",
  "operateTime": "2026-04-18 09:30:00",
  "orders": [
    {
      "orderId": "ORD-10001",
      "doctorMainStatus": "SIGNED",
      "baseDrugFlag": true,
      "dispenseMode": "IN_HOSPITAL_DISPENSE",
      "retainDrugMode": "CENTER_RETAIN",
      "dispenseQty": 3,
      "nurseRemark": "今日先发 3 天药量"
    },
    {
      "orderId": "ORD-10002",
      "doctorMainStatus": "VOID",
      "nurseRemark": "医生已作废，护士补签收"
    }
  ]
}
```

### 4.2.7.3.3.3 输出结果

系统处理成功后，输出结果包括：

- 医生站属性更新结果；
- `outp_nurse_order_ext` 写入或更新结果；
- 每条医嘱的最终展示状态；
- 签收成功/失败明细；
- 同步状态及日志记录结果。

输出示例如下：

```json
{
  "success": true,
  "signBatchNo": "SIGN-20260418-001",
  "resultList": [
    {
      "orderId": "ORD-10001",
      "nurseSignStatus": "SIGNED_OFF",
      "displayStatus": "已签收",
      "message": "签收成功"
    },
    {
      "orderId": "ORD-10002",
      "nurseSignStatus": "VOID_SIGNED_OFF",
      "displayStatus": "作废已签收",
      "message": "签收成功"
    }
  ],
  "message": "批量签收成功"
}
```

## 4.2.7.3.4 医嘱属性编辑输入输出

### 4.2.7.3.4.1 场景说明

护士在医嘱列表中点击“编辑”按钮后，可对医生站放开的医嘱属性进行补充维护。药品医嘱与非药品医嘱的可编辑范围不同，病理项目不允许编辑。

护士站仅负责发起编辑与补充回写，实际可编辑字段范围由医生站接口返回结果控制。

### 4.2.7.3.4.2 输入内容

输入内容主要包括：

- 接诊主键；
- 医嘱主键；
- 医嘱类别；
- 待修改属性集合；
- 操作护士信息；
- 操作时间。

输入示例如下：

```json
{
  "checkinId": "NC-20260418-0001",
  "orderId": "ORD-10001",
  "orderCategory": "DRUG",
  "operatorId": "N2001",
  "operatorName": "李护士",
  "operateTime": "2026-04-18 09:25:00",
  "editableFields": {
    "baseDrugFlag": true,
    "expressFlag": false,
    "calendarPackFlag": true,
    "dispenseQty": 3,
    "tempNoChargeFlag": true,
    "tempNoChargeReason": "10天后可能回来做",
    "retainDrugMode": "CENTER_RETAIN",
    "batchDispenseNote": "4月18日发3天，4月21日再发"
  }
}
```

### 4.2.7.3.4.3 输出结果

系统处理成功后，输出结果包括：

- 医生站属性更新结果；
- `outp_nurse_order_ext` 中补充字段更新结果；
- 最新可展示属性摘要；
- 最新页面操作权限信息。

输出示例如下：

```json
{
  "success": true,
  "orderId": "ORD-10001",
  "updatedFields": {
    "baseDrugFlag": true,
    "calendarPackFlag": true,
    "dispenseQty": 3,
    "tempNoChargeFlag": true,
    "retainDrugMode": "CENTER_RETAIN"
  },
  "message": "医嘱属性更新成功"
}
```

## 4.2.7.3.5 医嘱转录输入输出

### 4.2.7.3.5.1 场景说明

护士点击“转录”按钮时，调用医生站提供的医嘱开立组件，由医生站按权限规则控制护士角色可转录的医嘱类型。

护士站本模块不直接写医嘱主记录，仅负责传递上下文、承接组件返回结果，并在需要时刷新医嘱列表展示。

### 4.2.7.3.5.2 输入内容

输入内容主要包括：

- 接诊主键；
- 门诊就诊主键；
- 患者主键；
- 当前诊区及医生信息；
- 调用来源；
- 护士信息。

输入示例如下：

```json
{
  "checkinId": "NC-20260418-0001",
  "encounterId": "OP202604180001",
  "patientId": "P00012345",
  "clinicId": "OPD-ENT-01",
  "doctorId": "D1001",
  "operatorId": "N2001",
  "operatorName": "李护士",
  "source": "OUTPATIENT_NURSE_ORDER"
}
```

### 4.2.7.3.5.3 输出结果

组件返回结果主要包括：

- 是否转录成功；
- 新开立医嘱主键集合；
- 是否需医生确认；
- 是否进入审批流程；
- 刷新列表所需标识。

输出示例如下：

```json
{
  "success": true,
  "orderIds": ["ORD-20001", "ORD-20002"],
  "needDoctorConfirm": true,
  "needApproval": true,
  "refreshFlag": true,
  "message": "转录成功，待医生确认"
}
```

## 4.2.7.3.6 补记账与暂不收费输入输出

### 4.2.7.3.6.1 场景说明

护士可通过“补记账”按钮调用 HIS 记账组件进行补记账处理；同时，在签收药品医嘱时可将医嘱标记为“暂不收费”。

其中：

- 住院患者补记账、门诊患者补记账分别调用不同组件；
- “暂不收费”是护士站侧补充属性，主收费结果仍以 HIS 为准。

### 4.2.7.3.6.2 输入内容

输入内容主要包括：

- 接诊主键；
- 门诊就诊主键；
- 医嘱主键；
- 患者就诊类型；
- 暂不收费标记及原因；
- 操作人信息。

输入示例如下：

```json
{
  "checkinId": "NC-20260418-0001",
  "encounterId": "OP202604180001",
  "orderId": "ORD-10001",
  "patientVisitScope": "OUTPATIENT",
  "tempNoChargeFlag": true,
  "tempNoChargeReason": "未决定在养和做",
  "operatorId": "N2001",
  "operatorName": "李护士"
}
```

### 4.2.7.3.6.3 输出结果

系统处理成功后，输出结果包括：

- 补记账组件调用结果；
- 护士站扩展表中暂不收费字段回写结果；
- 页面收费标识刷新结果。

输出示例如下：

```json
{
  "success": true,
  "orderId": "ORD-10001",
  "billingComponentResult": "SUCCESS",
  "tempNoChargeFlag": true,
  "message": "补记账处理完成"
}
```

## 4.2.7.3.7 报价单导入医嘱输入输出

### 4.2.7.3.7.1 场景说明

护士打开护理文书中的费用预估单时，可选择导入当前医嘱数据生成正式报价单，也支持手工录入。护士站本模块负责传递当前就诊及医嘱上下文，不单独维护报价单主表。

### 4.2.7.3.7.2 输入内容

输入内容主要包括：

- 接诊主键；
- 门诊就诊主键；
- 患者主键；
- 选中的医嘱集合；
- 是否正式报价单；
- 护士信息。

输入示例如下：

```json
{
  "checkinId": "NC-20260418-0001",
  "encounterId": "OP202604180001",
  "patientId": "P00012345",
  "quoteType": "FORMAL",
  "selectedOrderIds": ["ORD-10001", "ORD-30001"],
  "operatorId": "N2001",
  "operatorName": "李护士"
}
```

### 4.2.7.3.7.3 输出结果

输出结果主要包括：

- 已导入的医嘱集合；
- 护理文书中生成的报价单标识；
- 是否允许打印；
- 是否允许继续补充手工项目。

输出示例如下：

```json
{
  "success": true,
  "quoteDocId": "QUOTE-20260418-0001",
  "importedOrderCount": 2,
  "printable": true,
  "message": "报价单生成成功"
}
```

## 4.2.7.3.8 医技预约输入输出

### 4.2.7.3.8.1 场景说明

护士点击“医技预约”按钮时，调用医技预约界面进行预约、修改、取消、查看操作。医技预约系统负责主业务处理，护士站模块只负责传递上下文并刷新展示结果。

### 4.2.7.3.8.2 输入内容

输入内容主要包括：

- 接诊主键；
- 门诊就诊主键；
- 医嘱主键；
- 患者主键；

```json
{

  "orderCategory": "EXAM",
```

### 4.2.7.3.8.3 输出结果

输出结果主要包括：


## 4.2.7.3.9 入院单查看输入输出

### 4.2.7.3.9.1 场景说明

护士点击患者列表中的入院单提醒图标，或右侧功能按钮【入院单】时，调用门诊医生站入院单组件。护士站本模块不维护入院单主数据，仅传递上下文并承接查看结果。

### 4.2.7.3.9.2 输入内容

输入内容主要包括：

- 接诊主键；
- 门诊就诊主键；
- 患者主键；
- 入院单业务主键（如已有）；
- 调用来源。

输入示例如下：

```json
{
  "checkinId": "NC-20260418-0001",
  "encounterId": "OP202604180001",
  "patientId": "P00012345",
  "admissionNoteId": "ADM-20260418-0001",
  "source": "OUTPATIENT_NURSE_ORDER"
}
```

### 4.2.7.3.9.3 输出结果

输出结果主要包括：

- 是否成功打开组件；
- 入院单主键；
- 入院单状态；
- 是否需刷新入院单提醒标识。

输出示例如下：

```json
{
  "success": true,
  "admissionNoteId": "ADM-20260418-0001",
  "status": "OPENED",
  "refreshFlag": false,
  "message": "打开成功"
}
```

## 4.2.7.3.10 统一输出约束

本模块所有输入输出场景统一遵循以下约束：

1. 医生站/HIS/药房/医技系统为主结果来源时，护士站仅做上下文透传与展示投影，不重复定义主结果语义；
2. 需要幂等控制的后台处理请求，统一以 `requestId` 作为请求唯一标识；
3. 后台处理失败时，统一写入 `outp_sync_status`；
4. 关键操作过程统一写入日志留痕机制；
5. 页面展示字段顺序、显隐、固定列范围及可编辑范围，统一受护士端配置控制。
