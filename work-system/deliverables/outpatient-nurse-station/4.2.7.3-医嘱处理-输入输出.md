# 4.2.7.3 输入、输出

## 4.2.7.3.1 设计说明

本模块输入输出设计围绕门诊护士站医嘱处理的核心使用链路展开，重点覆盖以下场景：

- 医嘱列表查询与展示；
- 医嘱签收；
- 医嘱属性编辑；
- 医嘱转录；
- 补记账与暂不收费；
- 报价单导入医嘱；
- 医技预约；
- 入院单查看。

其中：

1. 医嘱主数据、医嘱主状态、新废改、审方结果、收费主结果、转录主结果仍以医生站 / HIS / 药房 / 医技系统为准；
2. 护士站侧主要输出 `outp_nurse_order_ext` 中的签收结果、护士补充属性和少量展示投影字段；
3. 护士站允许签收“已签署”及“已作废”医嘱，不允许签收“待确认”及未审批生效的转录医嘱；
4. 若护士在签收前编辑了医嘱属性，则需先调用医生站接口完成属性更新，再回写护士站扩展数据。

## 4.2.7.3.2 医嘱列表查询与展示输入输出

### 4.2.7.3.2.1 场景说明

护士打开患者右侧医嘱处理区域时，系统需加载本次就诊相关的医嘱列表，并展示医生站主状态、护士签收状态、医嘱变更标识、新增标签及可编辑属性摘要。

医嘱列表以医生站医嘱主数据为基础，结合 `outp_nurse_order_ext` 进行展示组装。

### 4.2.7.3.2.2 输入内容

输入内容主要包括：

- 接诊主键；
- 门诊就诊主键；
- 患者主键；
- 医嘱分类筛选条件；
- 是否仅看未签收；
- 医嘱状态筛选条件；
- 页面显示配置版本。

输入示例如下：

```json
{
  "checkinId": "NC-20260418-0001",
  "encounterId": "OP202604180001",
  "patientId": "P00012345",
  "orderCategory": "ALL",
  "onlyUnsign": false,
  "statusList": ["SIGNED", "VOID", "PENDING_CONFIRM"],
  "displayConfigVersion": "NURSE-ORDER-DISPLAY-V1"
}
```

### 4.2.7.3.2.3 输出结果

系统加载成功后，输出结果包括：

- 医生站医嘱列表；
- 护士站扩展属性摘要；
- 页面展示状态；
- 新 / 废 / 改标识；
- 标签信息，如基数药、分批发药、诊间用药、审方结果、收费结果等；
- 是否允许签收、是否允许编辑、是否允许查看详情等页面操作控制信息。

输出示例如下：

```json
{
  "success": true,
  "checkinId": "NC-20260418-0001",
  "items": [
    {
      "orderId": "ORD-10001",
      "orderNo": "OPD-ORD-10001",
      "orderCategory": "DRUG",
      "orderItemName": "阿莫西林胶囊",
      "doctorMainStatus": "SIGNED",
      "nurseSignStatus": "UNSIGNED",
      "displayStatus": "已签署",
      "changeFlag": "NEW",
      "tags": ["诊间用药", "未收费"],
      "canSign": true,
      "canEdit": true,
      "canView": true
    }
  ],
  "message": "查询成功"
}
```

## 4.2.7.3.3 医嘱签收输入输出

### 4.2.7.3.3.1 场景说明

护士在医嘱列表中勾选医嘱后点击“签收”按钮，系统校验医嘱是否允许签收，并在必要时先更新医生站可编辑属性，再回写护士站签收结果。

当前收敛口径如下：

- 可签收：医生主状态为“已签署”或“已作废”的医嘱；
- 不可签收：待确认医嘱、未审批生效的转录医嘱；
- 若签收对象中包含可编辑属性变更，则需先调医生站接口更新主数据；
- 医生已作废且护士完成签收后，页面展示状态为“作废已签收”。

### 4.2.7.3.3.2 输入内容

输入内容主要包括：

- 接诊主键；
- 门诊就诊主键；
- 签收批次号；
- 待签收医嘱列表；
- 护士侧补充属性；
- 签收护士信息；
- 操作时间。

输入示例如下：

```json
{
  "checkinId": "NC-20260418-0001",
  "encounterId": "OP202604180001",
  "signBatchNo": "SIGN-20260418-001",
  "operatorId": "N2001",
  "operatorName": "李护士",
  "operateTime": "2026-04-18 09:30:00",
  "orders": [
    {
      "orderId": "ORD-10001",
      "doctorMainStatus": "SIGNED",
      "baseDrugFlag": true,
      "dispenseMode": "IN_HOSPITAL_DISPENSE",
      "retainDrugMode": "CENTER_RETAIN",
      "dispenseQty": 3,
      "nurseRemark": "今日先发 3 天药量"
    },
    {
      "orderId": "ORD-10002",
      "doctorMainStatus": "VOID",
      "nurseRemark": "医生已作废，护士补签收"
    }
  ]
}
```

### 4.2.7.3.3.3 输出结果

系统处理成功后，输出结果包括：

- 医生站属性更新结果；
- `outp_nurse_order_ext` 写入或更新结果；
- 每条医嘱的最终展示状态；
- 签收成功/失败明细；
- 同步状态及日志记录结果。

输出示例如下：

```json
{
  "success": true,
  "signBatchNo": "SIGN-20260418-001",
  "resultList": [
    {
      "orderId": "ORD-10001",
      "nurseSignStatus": "SIGNED_OFF",
      "displayStatus": "已签收",
      "message": "签收成功"
    },
    {
      "orderId": "ORD-10002",
      "nurseSignStatus": "VOID_SIGNED_OFF",
      "displayStatus": "作废已签收",
      "message": "签收成功"
    }
  ],
  "message": "批量签收成功"
}
```

## 4.2.7.3.4 医嘱属性编辑输入输出

### 4.2.7.3.4.1 场景说明

护士在医嘱列表中点击“编辑”按钮后，可对医生站放开的医嘱属性进行补充维护。药品医嘱与非药品医嘱的可编辑范围不同，病理项目不允许编辑。

护士站仅负责发起编辑与补充回写，实际可编辑字段范围由医生站接口返回结果控制。

### 4.2.7.3.4.2 输入内容

输入内容主要包括：

- 接诊主键；
- 医嘱主键；
- 医嘱类别；
- 待修改属性集合；
- 操作护士信息；
- 操作时间。

输入示例如下：

```json
{
  "checkinId": "NC-20260418-0001",
  "orderId": "ORD-10001",
  "orderCategory": "DRUG",
  "operatorId": "N2001",
  "operatorName": "李护士",
  "operateTime": "2026-04-18 09:25:00",
  "editableFields": {
    "baseDrugFlag": true,
    "expressFlag": false,
    "calendarPackFlag": true,
    "dispenseQty": 3,
    "tempNoChargeFlag": true,
    "tempNoChargeReason": "10天后可能回来做",
    "retainDrugMode": "CENTER_RETAIN",
    "batchDispenseNote": "4月18日发3天，4月21日再发"
  }
}
```

### 4.2.7.3.4.3 输出结果

系统处理成功后，输出结果包括：

- 医生站属性更新结果；
- `outp_nurse_order_ext` 中补充字段更新结果；
- 最新可展示属性摘要；
- 最新页面操作权限信息。

输出示例如下：

```json
{
  "success": true,
  "orderId": "ORD-10001",
  "updatedFields": {
    "baseDrugFlag": true,
    "calendarPackFlag": true,
    "dispenseQty": 3,
    "tempNoChargeFlag": true,
    "retainDrugMode": "CENTER_RETAIN"
  },
  "message": "医嘱属性更新成功"
}
```

## 4.2.7.3.5 外部组件调用输入输出摘要

### 4.2.7.3.5.1 设计说明

转录、补记账、报价单、医技预约、入院单等场景，本质上均为调用医生站、HIS、护理文书或医技系统的既有组件/模块，不属于本模块自行承接主业务结果的输入输出范畴。

因此，本节仅保留摘要说明，用于明确：

- 护士站在调用前需要透传哪些上下文；
- 外部组件返回后，本模块需要接收哪些结果用于页面刷新；
- 哪些结果只允许作为展示投影，不允许在本模块内重新定义主语义。

各场景的详细调用协议、接口入参与返回约束，统一放在 `4.2.7.4 模块接口` 中说明。

### 4.2.7.3.5.2 外部组件调用摘要

#### 1. 医嘱转录

- 调用对象：门诊医生站医嘱转录组件；
- 护士站透传内容：`checkinId`、`encounterId`、`patientId`、当前诊区及医生信息、操作护士信息；
- 组件返回内容：是否转录成功、新开立医嘱主键集合、是否需医生确认、是否进入审批流程、是否刷新列表；
- 本模块处理原则：不直接写医生站医嘱主表，仅在返回成功后刷新医嘱列表；待确认或待审批医嘱不可签收。

#### 2. 补记账

- 调用对象：HIS 补记账组件；
- 护士站透传内容：门诊/住院患者上下文、医嘱主键、患者就诊类型、操作护士信息；
- 组件返回内容：补记账结果、费用处理状态、是否需要刷新收费标识；
- 本模块处理原则：主收费结果以 HIS 为准；若护士签收时勾选了“暂不收费”，仅回写护士站扩展字段，不覆盖 HIS 主结果。

#### 3. 报价单

- 调用对象：护理文书中的费用预估单 / 报价单组件；
- 护士站透传内容：当前患者、当前就诊、选中的医嘱集合、报价类型、操作护士信息；
- 组件返回内容：报价单主键、导入的医嘱数量、是否允许打印、是否需要刷新页面；
- 本模块处理原则：不维护报价单主表，仅负责透传上下文和在必要时刷新展示结果。

#### 4. 医技预约

- 调用对象：医技预约组件 / 医技预约系统；
- 护士站透传内容：`checkinId`、`encounterId`、`patientId`、`orderId`、医嘱类别、调用来源；
- 组件返回内容：预约主键、预约状态、预约时间、是否需要刷新列表；
- 本模块处理原则：医技预约主结果由医技系统维护，本模块仅按展示需要接收少量投影结果。

#### 5. 入院单

- 调用对象：门诊医生站入院单组件；
- 护士站透传内容：`checkinId`、`encounterId`、`patientId`、入院单业务主键（如已有）、调用来源；
- 组件返回内容：是否打开成功、入院单主键、入院单状态、是否需刷新提醒标识；
- 本模块处理原则：不维护入院单主数据，仅负责上下文透传与提醒标识刷新。

## 4.2.7.3.6 统一输出约束

本模块所有输入输出场景统一遵循以下约束：

1. 医生站/HIS/药房/医技系统为主结果来源时，护士站仅做上下文透传与展示投影，不重复定义主结果语义；
2. 需要幂等控制的后台处理请求，统一以 `requestId` 作为请求唯一标识；
3. 后台处理失败时，统一写入 `outp_sync_status`；
4. 关键操作过程统一写入日志留痕机制；
5. 页面展示字段顺序、显隐、固定列范围及可编辑范围，统一受护士端配置控制。
