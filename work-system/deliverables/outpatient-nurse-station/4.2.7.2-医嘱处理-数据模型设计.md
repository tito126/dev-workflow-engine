# 4.2.7.2 数据模型设计（数据模型/库表结构）

> 图稿文件：`4.2.7.2-核心数据流转图.drawio`

## 4.2.7.2.1 设计目标

医嘱处理模块以门诊医生站现有医嘱主表为主数据源，护士站不重复建设医嘱主表，仅新增护士站辅助扩展表，用于承接护士站侧新增的签收结果、护士可编辑属性及少量业务跟踪字段。

本模块数据模型设计需满足以下目标：

1. 支撑护士站对医生已签署、已作废医嘱的查看与签收；
2. 支撑护士站对部分医嘱属性进行补充编辑；
3. 支撑药品、本中心执行、手术治疗、检查、检验等不同医嘱类型在护士站侧的差异化处理；
4. 保持与医生站、HIS、药房、医技系统的数据职责边界清晰，不复制外部系统主结果；
5. 为后续接口集成、列表展示、问题追溯与扩展演进预留稳定落点。

## 4.2.7.2.2 设计原则

### 4.2.7.2.2.1 主从分责原则

医生站现有医嘱表继续作为医嘱主数据来源，承接以下核心语义：

- 医嘱主记录及明细；
- 医嘱主状态，如待确认、已签署、已作废；
- 医嘱变更标识，如新、废、改；
- 审方结果；
- 收费主结果；
- 转录主结果；
- 医技预约、补记账、入院单等外部业务主结果。

护士站侧仅新增辅助扩展表，承接护士站独有或护士站主控的数据，不与医生站主表重复建模。

### 4.2.7.2.2.2 单张辅助表原则

结合当前需求边界，护士站新增字段总体仍属于“薄扩展”范畴，尚未达到按医嘱类型分别拆分子表的必要条件，因此本模块采用“单张辅助表 + 类型差异字段 + 扩展 JSON”的方式实现。

该方案具备以下优点：

- 查询路径简单，便于列表展示；
- 字段职责集中，便于需求持续收敛；
- 降低与医生站主表、外部系统主表的口径冲突；
- 便于后续按需要平滑演进为多表方案。

### 4.2.7.2.2.3 展示态组合原则

护士站页面展示的医嘱状态，不直接作为单独主状态落库，而是由“医生站主状态 + 护士签收状态”组合生成。

组合规则如下：

- 医生站主状态 = 待确认，且护士未签收 → 展示“待确认”；
- 医生站主状态 = 已签署，且护士未签收 → 展示“已签署”；
- 医生站主状态 = 已签署，且护士已签收 → 展示“已签收”；
- 医生站主状态 = 已作废，且护士未签收 → 展示“已作废”；
- 医生站主状态 = 已作废，且护士已签收 → 展示“作废已签收”。

其中，护士站允许签收“已签署”及“已作废”医嘱，不允许签收“待确认”及未审批生效的转录医嘱。

### 4.2.7.2.2.4 差异化承接原则

不同医嘱类型在护士站侧的数据承接范围不同：

1. **药品类医嘱**  
   重点承接基数药、快递、日历式包药机、已线下发药、发药数量、暂不收费、留药方式、分批发药说明、备注等护士侧补充属性。

2. **本中心执行类医嘱**  
   重点承接护士站侧少量执行跟踪信息，不复制计费主结果及执行记录主数据。

3. **手术治疗类医嘱**  
   重点承接本院/外院执行、申请单、预约、报告跟踪等少量护士侧辅助字段，不复制手术治疗系统主结果。

4. **检查类医嘱**  
   重点承接预约、报告跟踪、医生提醒等护士站侧辅助字段，不复制检查系统主结果。

5. **检验类医嘱**  
   重点承接标本采集、加验、报告跟踪等护士站侧辅助字段，不复制检验系统主结果。

## 4.2.7.2.3 核心数据模型

本模块采用如下建模方式：

- **医生站医嘱主表**：继续作为主数据源；
- **护士站医嘱扩展表 `outp_nurse_order_ext`**：作为本模块新增核心业务表；
- **外部系统业务表**：如医技预约、补记账、执行记录、报告结果等，仍由对应系统负责，不在本模块重复建表。

其中，`outp_nurse_order_ext` 负责承接护士站新增属性和签收结果，是 `4.2.7` 章节的核心新增表。

整体数据流转关系如下：

1. 医生站完成开立、签署、作废、转录后，医嘱主数据保留在医生站权威主表中；
2. 护士站查询医嘱列表时，以医生站医嘱主数据为基础，结合 `outp_nurse_order_ext` 进行页面组装；
3. 护士对医嘱执行签收或补充编辑时，先调用医生站接口完成主数据校验与属性更新，再更新 `outp_nurse_order_ext`；
4. 药房、HIS、医技系统返回的审方、收费、预约、报告等主结果，仍以外部系统为准，护士站仅按展示、提醒或追溯需要写少量投影字段；
5. 新增接口统一复用 `4.2.3` 的 `outp_sync_status`、统一日志留痕、统一配置能力。

## 4.2.7.2.4 表结构设计

### 4.2.7.2.4.1 表1：门诊护士站医嘱扩展表（outp_nurse_order_ext）

**用途**

用于存储护士站对医生站医嘱的补充处理数据，包括护士签收结果、护士可编辑属性、不同医嘱类型在护士站侧产生的少量辅助字段。

**数据来源**

- 医生站医嘱主数据关联结果；
- 护士站签收操作；
- 护士站编辑医嘱属性操作；
- 药房、医技、执行流程返回后由护士站侧补充的少量跟踪字段；
- 外部系统返回结果在护士站侧形成的展示或提醒性投影。

**设计说明**

1. 该表不是医嘱主表，不承接医嘱主状态语义；
2. 该表与医生站医嘱主记录通过 `source_system + order_id` 唯一关联；
3. 该表中的 `nurse_sign_status` 仅表示护士站签收状态；
4. 药品类高频字段采用固定列方式落库；
5. 检查、检验、手术治疗、本中心执行等少量差异字段采用“固定列 + 扩展 JSON”混合方式承接；
6. 未来若跟踪字段显著增加，可从本表平滑拆分出独立明细表。

## 4.2.7.2.5 关键字段说明

### 4.2.7.2.5.1 护士签收状态字段

`nurse_sign_status` 仅用于描述护士站侧签收结果，建议枚举如下：

- `UNSIGNED`：未签收；
- `SIGNED_OFF`：已签收；
- `VOID_SIGNED_OFF`：作废已签收。

该字段不替代医生站主状态，而是与医生站主状态组合生成页面最终展示态。

### 4.2.7.2.5.2 领药/发药方式字段

`dispense_mode` 用于承接药品类医嘱在护士站侧关注的发药方式，建议枚举包括：

- `SELF_PREPARED`：自备；
- `OUTSIDE_PURCHASE`：外出购药；
- `IN_HOSPITAL_DISPENSE`：院内发药。

该字段表达的是“药如何取得/发放”，与“药留在哪里”不是同一概念。

### 4.2.7.2.5.3 留药方式字段

`retain_drug_mode` 用于承接诊间留针场景，建议枚举如下：

- `CENTER_RETAIN`：中心留针；
- `PHARMACY_RETAIN`：药房留针；
- `NO_RETAIN`：不留针。

该字段表达的是药品发出后的留存位置，应与 `dispense_mode` 分开设计。

### 4.2.7.2.5.4 差异化扩展字段

`biz_ext_json` 用于承接当前尚未稳定为固定列、但在护士站侧需要保留的类型差异字段，例如：

- 本中心执行过程中的执行提醒信息；
- 手术治疗的外部协同信息；
- 检查、检验流程中的补充展示字段；
- 后续产品继续细化但暂未稳定的护士侧属性。

该字段作为扩展承接手段，不宜替代高频筛选或高频统计字段。

## 4.2.7.2.6 索引设计建议

为支撑护士站医嘱列表查询、签收操作和问题追溯，建议建立以下索引：

1. 唯一索引：`uk_source_order (source_system, order_id)`  
   用于保证同一来源系统下医嘱扩展记录唯一；

2. 普通索引：`idx_encounter_id`  
   用于按本次就诊查询医嘱扩展信息；

3. 普通索引：`idx_checkin_id`  
   用于按护士站接诊记录查询；

4. 普通索引：`idx_patient_id`  
   用于患者维度追溯；

5. 普通索引：`idx_sign_status`  
   用于待签收、已签收、作废已签收等状态筛选；

6. 普通索引：`idx_order_category`  
   用于按药品、检查、检验、手术治疗等类别排序和过滤。

## 4.2.7.2.7 数据流转说明

### 4.2.7.2.7.1 医嘱查看

护士站查询医嘱列表时，以医生站医嘱主数据为基础，关联 `outp_nurse_order_ext` 补充护士侧数据，共同生成页面展示结果。

### 4.2.7.2.7.2 医嘱签收

护士勾选“已签署”或“已作废”医嘱后执行签收：

1. 若医嘱存在护士侧可编辑属性变更，先调用医生站接口更新可编辑属性；
2. 医生站更新成功后，护士站写入或更新 `outp_nurse_order_ext`；
3. 将 `nurse_sign_status` 更新为 `SIGNED_OFF` 或 `VOID_SIGNED_OFF`；
4. 记录签收人、签收时间、签收批次号等信息。

### 4.2.7.2.7.3 医嘱属性编辑

护士站仅允许编辑产品明确放开的属性，且是否可编辑以医生站接口返回结果为准。编辑成功后，医生站主数据更新，护士站同步更新扩展表中的对应补充字段。

### 4.2.7.2.7.4 外部结果承接

补记账、医技预约、执行记录、报告结果等外部结果，不在护士站本模块重复建主表。如护士站页面展示、提醒或追溯需要，可按需回写少量投影字段到 `outp_nurse_order_ext`。

### 4.2.7.2.7.5 公共基础设施复用

参考 `4.2.3.2` 及既有门诊护士站章节口径，本模块新增接口与处理流程统一复用以下公共基础设施：

1. `outp_sync_status`：承接接口级幂等、重试、对账补偿；
2. 统一日志留痕机制：承接接口接收、处理、更新、异常、重试、幂等命中等关键动作；
3. 统一配置能力：承接护士端医嘱显示配置、字段显隐、字段顺序、开关配置等运行参数。

上述基础设施不计入本章节新增业务表，但属于本模块正式落地的必要依赖。
