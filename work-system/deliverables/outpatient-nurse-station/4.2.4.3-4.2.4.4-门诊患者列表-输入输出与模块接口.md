# 4.2.4.3-4.2.4.4 门诊患者列表详设内容

## 4.2.4.3 输入、输出

### 4.2.4.3.1 设计说明

本模块当前主要覆盖以下三类输入输出场景：

- HIS Check In 接诊写入；
- 外部系统写入患者流转；
- 护士手工处理患者流向与结束就诊。

### 4.2.4.3.2 HIS Check In 接诊写入输入输出

#### 4.2.4.3.2.1 场景说明

HIS 在患者完成门诊 check in 时，调用我方接口生成或更新门诊护士接诊记录。
若本次 check in 存在医嘱预约来源信息，则同步补充写入 `outp_nurse_checkin_order`，用于关联 `4.2.3.2.3.1.6` 的预约/医嘱来源数据。

#### 4.2.4.3.2.2 输入内容

输入内容主要包括：

- 请求唯一标识；
- 来源系统信息；
- 患者基础信息；
- 门诊就诊信息；
- 当前诊区与接诊医生信息；
- 就诊类型、诊疗目的、看诊方式等登记信息；
- 医嘱预约来源信息（如有）。

输入示例如下：

```json
{
  "requestId": "CHK-20260417-0001",
  "sourceSystem": "HIS",
  "encounterId": "OP202604170001",
  "patientId": "P00012345",
  "patientNameCn": "陈小明",
  "patientNameEn": "CHAN SIU MING",
  "gender": "M",
  "birthDate": "1990-01-01",
  "clinicId": "OPD-ENT-01",
  "clinicName": "耳鼻喉中心",
  "visitType": "普通门诊",
  "serviceType": "复诊",
  "doctorId": "D1001",
  "doctorName": "王医生",
  "consultMode": "亲身",
  "checkinTime": "2026-04-17 09:05:00",
  "checkinOrder": {
    "checkinOrderId": "CO-20260417-001",
    "sourceType": "医嘱",
    "appointmentId": "APT-8899",
    "inpEncounterId": "IP-998877",
    "orderId": "ORD-123456"
  }
}
```

#### 4.2.4.3.2.3 输出结果

系统接收并校验成功后，输出结果包括：

- 生成或更新 `outp_nurse_checkin` 主记录；
- 如存在医嘱预约来源，则写入或更新 `outp_nurse_checkin_order`；
- 返回接诊主键、来源关联主键及当前状态；
- 记录同步状态和处理日志。

输出示例如下：

```json
{
  "success": true,
  "checkinId": "NC-20260417-0001",
  "checkinOrderId": "CO-20260417-001",
  "currentStatus": "待分流",
  "message": "处理成功"
}
```

### 4.2.4.3.3 外部系统写入患者流转输入输出

#### 4.2.4.3.3.1 场景说明

门诊、分诊、医生站、检查等系统在患者完成候诊、叫号、就诊中、外出检查、已结束等节点后，通过护士站提供的统一接口写入患者流转事件。
该类事件统一沉淀到 `outp_nurse_transfer`，并按规则回写 `outp_nurse_checkin` 当前态。

#### 4.2.4.3.3.2 输入内容

输入内容主要包括：

- 请求唯一标识；
- 来源系统和来源事件标识；
- 接诊主键、患者主键、门诊就诊主键；
- 流转节点信息；
- 当前去向信息；
- 诊区、医生、操作时间等上下文；
- 是否为逆流程/撤销事件。

输入示例如下：

```json
{
  "requestId": "TRF-20260417-0101",
  "sourceSystem": "TRIAGE",
  "sourceEventId": "TRIAGE-EVT-9001",
  "checkinId": "NC-20260417-0001",
  "patientId": "P00012345",
  "encounterId": "OP202604170001",
  "nodeCode": "WAITING",
  "nodeName": "候诊中",
  "directionCode": "WAITING_AREA",
  "directionName": "候诊区",
  "clinicId": "OPD-ENT-01",
  "clinicName": "耳鼻喉中心",
  "doctorId": "D1001",
  "doctorName": "王医生",
  "transferTime": "2026-04-17 09:08:00",
  "reverseFlag": false,
  "remark": "分诊完成，进入候诊"
}
```

#### 4.2.4.3.3.3 输出结果

系统接收并校验成功后，输出结果包括：

- 生成 `outp_nurse_transfer` 流转事件记录；
- 更新 `outp_nurse_checkin` 当前状态、当前去向、最近事件信息；
- 按规则派生或失效相关标签；
- 记录同步状态和处理日志。

输出示例如下：

```json
{
  "success": true,
  "transferId": "NT-20260417-0101",
  "checkinId": "NC-20260417-0001",
  "currentStatus": "待接诊",
  "currentDestinationName": "候诊区",
  "message": "处理成功"
}
```

### 4.2.4.3.4 护士手工处理患者流向与结束就诊输入输出

#### 4.2.4.3.4.1 场景说明

护士在患者列表中可执行示踪补录、回本中心、结束就诊、提前结束就诊等操作。
该类操作由前端弹框提交到后台后，统一写入 `outp_nurse_transfer`，并同步更新 `outp_nurse_checkin` 当前态、去向摘要及 check out 结果。

#### 4.2.4.3.4.2 输入内容

输入内容主要包括：

- 接诊主键；
- 操作类型；
- 流向信息或 check out 信息；
- 是否提前结束；
- 结束原因或补录备注；
- 操作人及操作时间。

输入示例如下：

```json
{
  "checkinId": "NC-20260417-0001",
  "operationType": "CHECK_OUT",
  "directionCode": "LEAVE_HOSPITAL",
  "directionName": "离院",
  "checkOutReason": "离院",
  "prematureEndFlag": false,
  "operateTime": "2026-04-17 10:30:00",
  "operatorId": "N2001",
  "operatorName": "李护士",
  "remark": "患者就诊结束后离院"
}
```

#### 4.2.4.3.4.3 输出结果

系统完成校验后，输出结果包括：

- 生成新的 `outp_nurse_transfer` 事件记录；
- 更新 `outp_nurse_checkin` 中的当前状态、check out 标记、结束原因、当前去向；
- 如涉及 check out 后续引用，则保存引用快照摘要；
- 记录日志并刷新患者列表数据。

输出示例如下：

```json
{
  "success": true,
  "transferId": "NT-20260417-0201",
  "checkinId": "NC-20260417-0001",
  "currentStatus": "check out",
  "checkOutFlag": true,
  "message": "结束就诊成功"
}
```

## 4.2.4.4 模块接口

### 4.2.4.4.1 设计说明

本节接口分为三类：

- 后台接口；
- 前端组件调用协议；
- 我方主动通知其他系统接口。

### 4.2.4.4.2 后台接口

#### 4.2.4.4.2.1 HIS Check In 接诊写入接口

接口地址：`POST /api/outpatient-nurse/checkin/push`

功能说明：接收 HIS 发起的门诊 check in 请求，生成或更新 `outp_nurse_checkin`，并在必要时补充写入 `outp_nurse_checkin_order`。

调用方：HIS。

触发时机：患者完成门诊 check in 时。

请求参数：

- requestId；
- sourceSystem；
- encounterId；
- 患者基础信息；
- 当前诊区信息；
- 当前登记/接诊医生信息；
- 就诊类型、诊疗目的、看诊方式；
- checkinOrder 关联信息（如有）。

返回结果：

- 是否处理成功；
- checkinId；
- checkinOrderId（如有）；
- 当前状态。

异常处理：

- 使用 requestId 进行幂等校验；
- 失败时写入 `outp_sync_status`；
- 关键处理过程写入统一日志留痕机制；
- 重试与对账策略复用 `4.2.3.5.8`。

#### 4.2.4.4.2.2 外部系统写入患者流转接口

接口地址：`POST /api/outpatient-nurse/transfer/push`

功能说明：接收门诊、分诊、医生站、检查等系统推送的患者流转节点，生成 `outp_nurse_transfer` 记录，并同步更新 `outp_nurse_checkin` 当前态。

调用方：门诊、分诊、医生站、检查等系统。

触发时机：患者在候诊、叫号、就诊中、外出检查、已结束等节点发生状态变化时。

请求参数：

- requestId；
- sourceSystem；
- sourceEventId；
- checkinId；
- patientId；
- encounterId；
- nodeCode、nodeName；
- directionCode、directionName；
- clinicId、clinicName；
- doctorId、doctorName；
- transferTime；
- reverseFlag；
- remark。

返回结果：

- 是否处理成功；
- transferId；
- 当前状态；
- 当前去向；
- 是否需要刷新前端列表。

异常处理：

- 使用 requestId + sourceEventId 进行幂等校验；
- 当前态回写失败时记录异常；
- 失败时写入 `outp_sync_status`；
- 关键处理过程写入统一日志留痕机制。

#### 4.2.4.4.2.3 外部系统撤销/逆流程接口

接口地址：`POST /api/outpatient-nurse/transfer/reverse`

功能说明：接收外部系统发起的撤销、逆流程、回退事件请求，生成逆向事件并修正当前有效事件状态。

调用方：门诊、分诊、医生站、检查等系统。

触发时机：外部系统发现前序节点误操作、患者返回本中心或需要撤销历史事件时。

请求参数：

- requestId；
- sourceSystem；
- sourceEventId；
- checkinId；
- reversedTransferId；
- reverseReason；
- currentNodeCode；
- currentDirectionCode；
- operateTime。

返回结果：

- 是否处理成功；
- 新生成的 reverse transferId；
- 被撤销事件处理结果；
- 当前状态。

异常处理：

- 先进行幂等校验；
- 若被撤销事件不存在，则返回失败说明；
- 处理结果写入 `outp_sync_status` 与统一日志；
- 详细处理规则详见 `4.2.4.2.2.4`。

#### 4.2.4.4.2.4 患者列表查询接口

接口地址：`GET /api/outpatient-nurse/patient/list`

功能说明：按患者列表页面的查询条件，返回当前诊区患者列表数据。

调用方：门诊护士站前端页面。

触发时机：页面初始化、筛选查询、刷新界面时。

请求参数：

- clinicId；
- bizDate；
- tabType；
- statusList；
- attendDoctorId；
- consultMode；
- noConsultFlag；
- keyword；
- pageNo、pageSize。

返回结果：

- 患者列表分页数据；
- 每条记录的当前态字段；
- 当前有效标签；
- 最近示踪摘要；
- 最近刷新时间。

异常处理：

- 参数非法时返回失败信息；
- 查询异常时写错误日志；
- 不通过 `outp_sync_status` 处理幂等，但需保留访问日志。

### 4.2.4.4.3 前端组件调用协议

#### 4.2.4.4.3.1 患者分流弹框调用协议

调用场景：护士在患者列表中点击“分流”操作，对患者执行分流处理。

调用入口：患者列表操作列中的【分流】按钮。

核心入参：

- checkinId；
- patientId；
- currentStatus；
- clinicId；
- doctorId；
- triageContext（如有）；
- vitalSummary（如有）。

核心出参：

- 是否处理成功；
- transferId；
- 最新状态；
- 是否需要刷新当前列表。

调用后处理：

- 成功后刷新患者列表；
- 后端写入 `outp_nurse_transfer` 并更新 `outp_nurse_checkin`；
- 如涉及标签变化，同步更新标签结果。

#### 4.2.4.4.3.2 患者示踪弹框调用协议

调用场景：护士查看患者示踪记录，或新增患者流向补录记录。

调用入口：患者列表操作列中的【示踪】按钮。

核心入参：

- checkinId；
- patientId；
- encounterId；
- operationType（查询/新增）；
- directionCode；
- directionName；
- remark。

核心出参：

- 是否处理成功；
- transferId（新增时）；
- 当前示踪记录列表；
- 是否需要刷新当前列表。

调用后处理：

- 新增成功后刷新时间轴与患者列表；
- 后端记录流转事件；
- 如当前去向发生变化，则同步更新主表当前态与去向标签。

#### 4.2.4.4.3.3 结束就诊弹框调用协议

调用场景：护士执行结束就诊或提前结束就诊。

调用入口：患者列表操作列中的【结束就诊】按钮。

核心入参：

- checkinId；
- checkOutReason；
- prematureEndFlag；
- prematureEndReason；
- postCheckOutRefInfo（如有）；
- operatorId、operatorName。

核心出参：

- 是否处理成功；
- transferId；
- checkOutFlag；
- 当前状态；
- 是否需要刷新界面。

调用后处理：

- 成功后刷新当前患者列表；
- 后端写入 check out 事件并更新当前态；
- 如涉及后续入院/转介引用，则同步保存摘要信息；
- 记录日志并保留必要的同步信息。

### 4.2.4.4.4 我方主动通知其他系统接口

#### 4.2.4.4.4.1 场景说明

当护士在患者列表中执行结束就诊、提前结束就诊、逆流程回退、回本中心等操作，且这些操作需要同步至分诊、医生站、康复等系统时，我方需按配置主动通知相关系统。

#### 4.2.4.4.4.2 通知内容

通知内容建议包含：

- 事件类型；
- checkinId；
- encounterId；
- transferId；
- 当前状态；
- 当前去向；
- 操作人信息；
- 操作时间；
- requestId。

#### 4.2.4.4.4.3 处理要求

- 回调地址和开关由统一配置维护；
- 回调失败时，需写入 `outp_sync_status`；
- 系统需支持后台定时重试；
- 超过最大重试次数后，应标记异常并提示人工处理；
- 通知日志需纳入统一日志留痕机制。
