# 4.2.7.3 输入、输出

## 4.2.7.3.1 设计说明

本模块输入输出设计围绕门诊护士站医嘱处理的核心使用链路展开，重点覆盖以下场景：

- 医嘱列表查询与展示
- 医嘱查看与执行计划展示
- 医嘱签收
- 医嘱属性编辑
- 外部组件调用与结果刷新

其中：

- 医嘱主数据、医嘱主状态、签收结果、新废改、审方结果、收费结果、转录结果等，仍以医生站、HIS、药房、医技系统返回结果为准。
- 护士站侧主要输出 `outp_nurse_order_ext` 中的护士站自有辅助字段，如留药方式、护士备注等。
- 是否允许签收、是否允许编辑、是否允许查看详情及是否展示执行计划等页面控制信息，以医生站返回结果、当前医嘱类型及页面配置共同确定。
- 护士进入医嘱处理页面后，需实时调用医生站接口获取当前医嘱允许编辑的属性范围，护士站不单独维护可编辑规则快照。

## 4.2.7.3.2 医嘱列表查询与展示输入输出

### 4.2.7.3.2.1 场景说明

护士打开患者右侧医嘱处理区域时，系统需加载本次就诊相关的医嘱列表，并展示医生站主状态、签收结果、医嘱变更标识及护士站自有辅助信息。医嘱列表以医生站医嘱主数据为基础，按需关联 `outp_nurse_order_ext` 进行展示组装。

查看按钮统一放置在医嘱处理区域顶部。护士选中医嘱后点击查看按钮，系统根据当前医嘱类型动态展示详情区内容；对于不涉及执行计划的医嘱类型，仅展示医嘱详情，不展示执行计划区域。

### 4.2.7.3.2.2 输入内容

输入内容主要包括：

- 接诊主键
- 门诊就诊主键
- 患者主键
- 医嘱分类筛选条件
- 是否仅看未签收
- 医嘱状态筛选条件
- 页面显示配置版本

输入示例如下：

```json
{
  "checkinId": "NC-20260418-0001",
  "encounterId": "OP202604180001",
  "patientId": "P00012345",
  "orderCategory": "ALL",
  "onlyUnsign": false,
  "statusList": ["SIGNED", "VOID", "PENDING_CONFIRM"],
  "displayConfigVersion": "NURSE-ORDER-DISPLAY-V1"
}
```

### 4.2.7.3.2.3 输出结果

系统加载成功后，输出结果包括：

- 医生站医嘱列表
- 护士站自有辅助属性摘要
- 页面展示状态
- 新、废、改标识
- 审方、收费、签收等结果摘要
- 是否允许签收、是否允许编辑、是否允许查看详情、是否展示执行计划等页面控制信息

输出示例如下：

```json
{
  "success": true,
  "checkinId": "NC-20260418-0001",
  "items": [
    {
      "orderId": "ORD-10001",
      "orderNo": "OPD-ORD-10001",
      "orderCategory": "DRUG",
      "orderItemName": "阿莫西林胶囊",
      "doctorMainStatus": "SIGNED",
      "signStatus": "UNSIGNED",
      "displayStatus": "已签署",
      "changeFlag": "NEW",
      "retainDrugMode": "CENTER_RETAIN",
      "canSign": true,
      "canEdit": true,
      "canView": true,
      "hasExecutionPlan": true
    }
  ],
  "message": "查询成功"
}
```

## 4.2.7.3.3 医嘱签收输入输出

### 4.2.7.3.3.1 场景说明

护士在医嘱列表中勾选医嘱后点击“签收”按钮，系统校验医嘱是否允许签收，并调用医生站签收接口完成处理。签收结果、签收状态及相关业务语义均以医生站返回结果为准，护士站不在本模块中单独维护签收状态体系。

当前收敛口径如下：

- 可签收：医生站返回允许签收的医嘱
- 不可签收：待确认医嘱、未审批生效的转录医嘱及医生站判定不允许签收的医嘱
- 护士站仅负责发起签收请求、接收处理结果并刷新页面展示

### 4.2.7.3.3.2 输入内容

输入内容主要包括：

- 请求唯一标识
- 接诊主键
- 门诊就诊主键
- 待签收医嘱列表
- 签收护士信息
- 操作时间

输入示例如下：

```json
{
  "requestId": "REQ-SIGN-20260418-0001",
  "checkinId": "NC-20260418-0001",
  "encounterId": "OP202604180001",
  "operatorId": "N2001",
  "operatorName": "李护士",
  "operateTime": "2026-04-18 09:30:00",
  "orders": [
    {
      "orderId": "ORD-10001",
      "doctorMainStatus": "SIGNED"
    },
    {
      "orderId": "ORD-10002",
      "doctorMainStatus": "VOID"
    }
  ]
}
```

### 4.2.7.3.3.3 输出结果

系统处理成功后，输出结果包括：

- 医生站签收处理结果
- 每条医嘱的签收成功或失败明细
- 每条医嘱的最新展示状态
- 是否需要刷新医嘱列表

输出示例如下：

```json
{
  "success": true,
  "resultList": [
    {
      "orderId": "ORD-10001",
      "signStatus": "SIGNED_OFF",
      "displayStatus": "已签收",
      "message": "签收成功"
    },
    {
      "orderId": "ORD-10002",
      "signStatus": "VOID_SIGNED_OFF",
      "displayStatus": "作废已签收",
      "message": "签收成功"
    }
  ],
  "needRefresh": true,
  "message": "批量签收成功"
}
```

## 4.2.7.3.4 医嘱属性编辑输入输出

### 4.2.7.3.4.1 场景说明

护士在医嘱列表中点击“编辑”按钮后，可对医生站放开的医嘱属性进行修改，并维护护士站自有辅助字段。实际可编辑字段范围以医生站接口实时返回结果为准，病理项目不允许编辑。

其中：

- 属于医生站主数据范围的字段，由医生站负责校验与更新
- 属于护士站自有业务范围的字段，如留药方式、护士备注等，由护士站落库到 `outp_nurse_order_ext`

### 4.2.7.3.4.2 输入内容

输入内容主要包括：

- 请求唯一标识
- 接诊主键
- 医嘱主键
- 医嘱类别
- 医生站可编辑字段集合
- 护士站自有字段集合
- 操作护士信息
- 操作时间

输入示例如下：

```json
{
  "requestId": "REQ-EDIT-20260418-0001",
  "checkinId": "NC-20260418-0001",
  "orderId": "ORD-10001",
  "orderCategory": "DRUG",
  "operatorId": "N2001",
  "operatorName": "李护士",
  "operateTime": "2026-04-18 09:25:00",
  "doctorEditableFields": {},
  "nurseOwnFields": {
    "retainDrugMode": "CENTER_RETAIN",
    "nurseRemark": "患者今日先留中心处理"
  }
}
```

### 4.2.7.3.4.3 输出结果

系统处理成功后，输出结果包括：

- 医生站字段更新结果
- 护士站自有字段更新结果
- 最新可展示属性摘要
- 最新页面操作权限信息

输出示例如下：

```json
{
  "success": true,
  "orderId": "ORD-10001",
  "doctorEditableResult": "SUCCESS",
  "updatedNurseFields": {
    "retainDrugMode": "CENTER_RETAIN",
    "nurseRemark": "患者今日先留中心处理"
  },
  "message": "医嘱属性更新成功"
}
```

## 4.2.7.3.5 外部组件调用输入输出摘要

### 4.2.7.3.5.1 设计说明

医嘱查看、转录、补记账、报价单、医技预约、入院单等场景，本质上均为调用医生站、HIS、护理文书或医技系统的既有组件或模块，不属于本模块自行承接主业务结果的输入输出范畴。

因此，本节仅保留摘要说明，用于明确：

- 护士站在调用前需要透传哪些上下文
- 外部组件返回后，本模块需要接收哪些结果用于页面刷新
- 哪些结果仅用于展示，不在本模块内重新定义主语义

各场景的详细调用协议、接口入参与返回约束，统一放在 4.2.7.4 模块接口中说明。

### 4.2.7.3.5.2 外部组件调用摘要

**医嘱查看与执行计划展示**

- 调用对象：门诊医生站医嘱详情查看组件
- 护士站透传内容：`checkinId`、`encounterId`、`patientId`、`orderId`、`orderCategory`
- 组件返回内容：医嘱详情、签收结果、审方和收费结果摘要、是否存在执行计划、执行计划内容
- 本模块处理原则：查看按钮统一放置于页面顶部，点击后根据医嘱类型动态展示详情与执行计划区域；对于无执行计划的医嘱类型，仅展示详情信息

**医嘱转录**

- 调用对象：门诊医生站医嘱转录组件
- 护士站透传内容：`checkinId`、`encounterId`、`patientId`、当前诊区及医生信息、操作护士信息
- 组件返回内容：是否转录成功、新开立医嘱主键集合、是否需医生确认、是否进入审批流程、是否刷新列表
- 本模块处理原则：不直接写医生站医嘱主表，仅在返回成功后刷新医嘱列表；待确认或待审批医嘱不可签收

**补记账**

- 调用对象：HIS 补记账组件
- 护士站透传内容：门诊或住院患者上下文、医嘱主键、患者就诊类型、操作护士信息
- 组件返回内容：补记账结果、费用处理状态、是否需要刷新收费标识
- 本模块处理原则：主收费结果以 HIS 为准，本模块不重复落库收费主结果

**报价单**

- 调用对象：护理文书中的费用预估单或报价单组件
- 护士站透传内容：当前患者、当前就诊、选中的医嘱集合、报价类型、操作护士信息
- 组件返回内容：报价单主键、导入的医嘱数量、是否允许打印、是否需要刷新页面
- 本模块处理原则：不维护报价单主表，仅负责透传上下文和在必要时刷新展示结果

**医技预约**

- 调用对象：医技预约组件或医技预约系统
- 护士站透传内容：`checkinId`、`encounterId`、`patientId`、`orderId`、`orderCategory`、调用来源
- 组件返回内容：预约主键、预约状态、预约时间、是否需要刷新列表
- 本模块处理原则：医技预约主结果由医技系统维护，本模块仅接收返回结果并按需刷新展示

**入院单**

- 调用对象：门诊医生站入院单组件
- 护士站透传内容：`checkinId`、`encounterId`、`patientId`、入院单业务主键（如已有）、调用来源
- 组件返回内容：是否打开成功、入院单主键、入院单状态、是否需刷新提醒标识
- 本模块处理原则：不维护入院单主数据，仅负责上下文透传与页面提醒刷新

### 4.2.7.3.5.3 统一输出约束

本模块所有输入输出场景统一遵循以下约束：

- 医生站、HIS、药房、医技系统为主结果来源时，护士站仅做上下文透传与页面展示，不重复定义主结果语义。
- 需要幂等控制的后台处理请求，统一以 `requestId` 作为请求唯一标识。
- 后台处理失败时，统一写入 `outp_sync_status`。
- 关键操作过程统一写入日志留痕机制。
- 页面展示字段顺序、显隐、固定列范围及按钮可用性，统一受护士端配置控制。
