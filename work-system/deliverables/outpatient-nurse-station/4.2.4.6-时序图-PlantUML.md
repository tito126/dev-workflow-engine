## 三、PlantUML 草稿

## 4.2.4.6.1 HIS Check In 接诊写入时序图

```plantuml
@startuml
hide footbox

autonumber

actor "HIS" as HIS
participant "Check In 接口\n/api/outpatient-nurse/checkin/push" as CheckinApi
participant "接诊处理服务" as CheckinService
database "outp_sync_status\n同步状态表" as SyncStatus
database "outp_nurse_checkin_order\n门诊接诊医嘱预约信息表" as CheckinOrder
database "outp_nurse_checkin\n门诊护士接诊表" as Checkin
collections "统一日志留痕机制" as OpLog

HIS -> CheckinApi: 推送 Check In 请求(requestId, patient, encounter, checkinOrder)
CheckinApi -> CheckinService: 校验并处理请求
CheckinService -> SyncStatus: 按 requestId 查询幂等状态
alt 已成功处理
    SyncStatus --> CheckinService: SUCCESS
    CheckinService --> CheckinApi: 直接返回既有处理结果
    CheckinApi --> HIS: success(idempotent=true)
else 未处理或处理失败
    SyncStatus --> CheckinService: NOT_FOUND / FAILED
    CheckinService -> SyncStatus: 写入 PENDING 状态
    alt 请求中包含医嘱预约来源信息
        CheckinService -> CheckinOrder: 新增或更新来源关联记录
        CheckinOrder --> CheckinService: 返回 checkinOrderId
    end
    CheckinService -> Checkin: 新增或更新接诊主记录
    Checkin --> CheckinService: 返回 checkinId
    CheckinService -> SyncStatus: 更新为 SUCCESS / FAILED
    CheckinService -> OpLog: 记录 Check In 处理日志
    CheckinService --> CheckinApi: 返回处理结果
    CheckinApi --> HIS: success/fail
end
@enduml
```

## 4.2.4.6.2 外部系统推送患者流转时序图

```plantuml
@startuml
hide footbox

autonumber

actor "门诊/分诊/医生站/检查系统" as Caller
participant "流转接口\n/api/outpatient-nurse/transfer/push" as TransferApi
participant "流转处理服务" as TransferService
database "outp_sync_status\n同步状态表" as SyncStatus
database "outp_nurse_transfer\n门诊护士示踪/流转表" as Transfer
database "outp_nurse_checkin\n门诊护士接诊表" as Checkin
database "outp_checkin_tag\n就诊标签表" as Tag
database "outp_checkin_tag_log\n标签日志表" as TagLog
collections "统一日志留痕机制" as OpLog

Caller -> TransferApi: 推送流转事件(requestId, sourceEventId, checkinId, node, direction)
TransferApi -> TransferService: 校验并处理流转事件
TransferService -> SyncStatus: 查询 requestId / sourceEventId 幂等状态
alt 已成功处理
    SyncStatus --> TransferService: SUCCESS
    TransferService --> TransferApi: 直接返回既有 transferId
    TransferApi --> Caller: success(idempotent=true)
else 未处理或处理失败
    SyncStatus --> TransferService: NOT_FOUND / FAILED
    TransferService -> SyncStatus: 写入 PENDING 状态
    TransferService -> Transfer: 新增流转事件记录
    Transfer --> TransferService: 返回 transferId
    TransferService -> Checkin: 回写当前状态/去向/最近事件
    alt 派生标签变化
        TransferService -> Tag: 新增/更新/失效相关标签
        TransferService -> TagLog: 记录标签变更日志
    end
    TransferService -> SyncStatus: 更新为 SUCCESS / FAILED
    TransferService -> OpLog: 记录流转处理日志
    TransferService --> TransferApi: 返回处理结果
    TransferApi --> Caller: success/fail
end
@enduml
```

    PatientPage --> Nurse: 展示新增成功
else 校验失败
    TraceService --> PatientPage: 返回失败原因
    PatientPage --> Nurse: 提示失败原因
end
@enduml

ReverseApi -> ReverseService: 校验并处理逆流程

Transfer --> ReverseService: 返回原始事件信息
alt 原事件存在
    ReverseService -> Transfer: 新增 reverse 事件
    ReverseService -> Transfer: 更新原事件有效性/撤销关联
    ReverseService -> Checkin: 重新归并并回写当前态
    ReverseService -> Tag: 修正相关标签
    ReverseService -> OpLog: 记录逆流程处理日志
    ReverseService --> ReverseApi: 返回成功
    ReverseApi --> Caller: success
else 原事件不存在
    ReverseService -> OpLog: 记录失败日志
    ReverseService --> ReverseApi: 返回失败原因
    ReverseApi --> Caller: fail(errorMessage)
end
@enduml

## 4.2.4.6.6 幂等、重试与对账处理时序图

```plantuml
@startuml
hide footbox

autonumber

actor "调用方" as Caller
participant "业务接口" as BizApi
participant "业务处理服务" as BizService
database "outp_sync_status\n同步状态表" as SyncStatus
database "核心业务表\ncheckin / transfer / tag" as BizTable
collections "统一日志留痕机制" as OpLog
participant "定时对账任务" as ReconcileJob

Caller -> BizApi: 发起请求(requestId, bizData)
BizApi -> BizService: 转发处理
BizService -> SyncStatus: 查询 requestId 幂等状态
alt 已成功处理
    SyncStatus --> BizService: SUCCESS
    BizService -> OpLog: 记录幂等命中日志
    BizService --> BizApi: 返回既有结果
    BizApi --> Caller: success(idempotent=true)
else 未处理或处理失败
    SyncStatus --> BizService: NOT_FOUND / FAILED
    BizService -> SyncStatus: 写入 PENDING 状态
    BizService -> BizTable: 执行业务落库
    alt 处理成功
        BizService -> SyncStatus: 更新为 SUCCESS
        BizService -> OpLog: 记录成功日志
        BizService --> BizApi: 返回成功
        BizApi --> Caller: success
    else 处理失败
        BizService -> SyncStatus: 更新为 FAILED\n并写 retry_count/next_retry_time/error
        BizService -> OpLog: 记录失败日志
        BizService --> BizApi: 返回失败原因
        BizApi --> Caller: fail(errorMessage)
    end
end

ReconcileJob -> SyncStatus: 查询 FAILED / PENDING 记录
SyncStatus --> ReconcileJob: 返回待处理记录
ReconcileJob -> BizService: 发起重试或对账修正
BizService -> BizTable: 补录 / 修正业务数据
BizService -> SyncStatus: 更新最终状态
BizService -> OpLog: 记录重试/对账日志
@enduml
```
