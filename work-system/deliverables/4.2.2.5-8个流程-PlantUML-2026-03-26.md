## 4.2.2.5.2 日程看板加载流程

```plantuml
@startuml
start
:用户进入日程看板/切换筛选条件;
:系统读取日期、诊区、科室、资源类型等条件;
:查询资源信息;
:查询资源排班主记录 outp_resource_sched;
:查询排班时段明细 outp_res_sched_detail;
:查询预约记录 outp_schedule_reserved;
:查询预约类型颜色配置;
:按资源+时间轴渲染看板;
:已预约数据按预约类型着色展示;
stop
@enduml
```

## 4.2.2.5.3 三方系统推送排班流程

```plantuml
@startuml
start
:接收三方排班推送请求;
:校验来源系统与必要参数;
if (参数是否有效?) then (是)
  :根据资源+日期+排班编号判断新增或更新;
  :写入/更新 outp_resource_sched;
  :拆分/更新 outp_res_sched_detail;
  :记录 outp_schedule_log;
  :返回处理成功;
else (否)
  :记录失败日志;
  :返回参数错误;
endif
stop
@enduml
```

## 4.2.2.5.4 护士手动新增日程流程

```plantuml
@startuml
start
:护士点击新增日程;
:填写资源、日期、时间、标题、备注等信息;
:系统校验资源是否可用;
:系统校验时间段是否冲突;
if (校验是否通过?) then (通过)
  :写入 outp_schedule_reserved;
  if (是否基于已有排班时段?) then (是)
    :按业务规则决定是否更新 outp_res_sched_detail 状态;
  else (否)
    :直接保留日程记录;
  endif
  :写入 outp_schedule_log;
  :返回创建成功并刷新看板;
else (不通过)
  :返回失败原因;
endif
stop
@enduml
```

## 4.2.2.5.5 调用预约组件处理预约流程

```plantuml
@startuml
start
:用户点击可预约时段或已预约记录;
:前端收集资源、时段、业务标识等信息;
:调用预约组件;
if (组件处理成功?) then (成功)
  :新增/更新/取消 outp_schedule_reserved;
  :按业务规则更新时段状态;
  :写入 outp_schedule_log;
  :如涉及三方交互则写入 outp_sync_status;
  :刷新日程看板;
else (失败)
  :提示处理失败;
endif
stop
@enduml
```

## 4.2.2.5.6 三方系统推送预约数据流程

```plantuml
@startuml
start
:接收三方预约推送请求;
:读取 requestId;
if (是否已成功处理?) then (是)
  :直接返回幂等成功;
else (否)
  :写入/更新 outp_sync_status = PENDING;
  :写入/更新 outp_schedule_reserved;
  if (是否包含医嘱信息?) then (是)
    :写入 outp_sched_order_resv;
  else (否)
  endif
  :更新 outp_sync_status 处理结果;
  :写入 outp_schedule_log;
  :返回处理结果;
endif
stop
@enduml
```

## 4.2.2.5.8 逆流程处理

```plantuml
@startuml
start
:接收逆流程事件;
if (事件类型?) then (三方取消排班)
  :查询排班记录;
  :检查是否存在关联预约;
  if (存在关联预约?) then (是)
    :标记待处理/异常;
  else (否)
    :取消或删除排班;
  endif
elseif (三方修改排班)
  :计算影响范围;
  :更新排班及相关展示数据;
elseif (三方取消预约)
  :定位预约记录;
  :更新预约状态;
  :按业务规则释放时段;
elseif (我方主动通知三方)
  :组装通知内容;
  :调用三方接口;
  if (回调失败?) then (是)
    :写入 outp_sync_status 等待重试;
  else (否)
    :记录成功日志;
  endif
endif
:写入 outp_schedule_log;
stop
@enduml
```

## 4.2.2.5.9 幂等、重试与对账处理流程

```plantuml
@startuml
start
:接收三方请求或扫描失败记录;
if (幂等校验已成功?) then (是)
  :直接返回已处理结果;
else (否)
  :执行正常业务逻辑;
  if (处理是否成功?) then (成功)
    :更新 outp_sync_status = SUCCESS;
  else (失败)
    :更新 outp_sync_status = FAILED;
    :计算 next_retry_time;
    if (重试次数是否超限?) then (否)
      :进入重试队列;
    else (是)
      :标记异常，等待人工处理;
    endif
  endif
endif
:定时执行对账任务;
:比对三方记录与我方记录;
if (存在差异?) then (是)
  :执行补录/重试/修正;
else (否)
  :结束;
endif
stop
@enduml
```
